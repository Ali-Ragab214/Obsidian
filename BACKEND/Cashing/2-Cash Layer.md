# 🧠 Cache vs Database Thinking (واحد من أهم أسرار الـ Scaling)

معظم الناس فاكرة إن backend = API + Database وخلاص.  
لكن الحقيقة في الأنظمة الكبيرة 👇  
**قاعدة ذهبية:**

> Database لازم تشتغل أقل وقت ممكن.

ليه؟ لأن الـ Database أبطأ وأغلى جزء في السيستم.

وهنا يدخل مفهوم مهم جدًا 👇

---

# 🚀 Caching (مش مجرد Performance… ده Survival)

الكاش = تخزين بيانات متكررة الاستخدام في مكان أسرع من الداتابيز.

بدل ما كل Request يروح للداتابيز، بنخلي معظم الريكوستس تخلص قبل ما توصل لها أصلاً.

وده سبب إن مواقع ضخمة زي  
Netflix  
أو Amazon تقدر تخدم ملايين المستخدمين.

---

## ليه الداتابيز خطر لوحدها؟ 😨

تخيل API عندك بيعمل:

```text
Get product by id
```

لو عندك 10,000 مستخدم:

- كل واحد بيفتح المنتج
    
- كل request يضرب DB
    

يعني آلاف queries في الثانية 💥  
الداتابيز هتختنق.

حتى لو عملت indexing… برضه مش كفاية.

---

# 💡 الحل: Cache Layer

نضيف طبقة بين الـ API والـ Database:

User → API → **Cache** → Database

الـ API يسأل الكاش الأول:

- لو لقى البيانات → يرجعها فورًا ⚡
    
- لو ملقهاش → يجيب من DB ويحفظها في الكاش.
    

ده اسمه:

## Cache Aside Pattern (لازم تحفظ الاسم ده)

الخطوات:  
1️⃣ API يسأل الكاش  
2️⃣ لو Miss → يجيب من DB  
3️⃣ يخزن في الكاش  
4️⃣ يرجع النتيجة

---

## ليه الكاش سريع جدًا؟

لأنه بيكون:

- في الـ RAM مش Disk
    
- Key/Value بسيط جدًا
    
- بدون joins ولا relations
    

سرعة:

- DB query: ~20–200 ms
    
- Cache read: ~1 ms 😳
    

فرق ضخم جدًا.

---

# 🔥 Types of Data لازم تتحط في Cache

Backend dev شاطر يعرف **إيه يتحط في الكاش وإيه لأ**.

### ينفع يتحط:

- Products
    
- Categories
    
- Settings
    
- Public profiles
    
- Lists & feeds
    
- Top rated workers (مهم لمشروعك 👀)
    

### ماينفعش:

- Transactions
    
- Payments
    
- Balance
    
- Real-time critical data
    

---

# ⚠️ أهم مشكلة في الكاش (الناس بتنساه)

## Cache Invalidation 😈

أصعب مشكلة في الـ backend.

السؤال:  
لو البيانات اتغيرت في DB… الكاش هيفضل فيه القديم 😬

لازم تمسحه أو تحدثه.

أشهر حل:

### TTL (Time To Live)

مثلاً:

- Product cache يعيش 5 دقايق
    
- بعد كده يتحدث تلقائي
    

---

# 🎯 ليه ده مهم جدًا لمشروعك؟

مشروع الخدمات بتاعك هيبقى فيه:

- Users كتير
    
- Workers كتير
    
- Requests كتير
    

لو كل طلب يقرأ من DB → هيقع بسرعة.

لكن مع caching:

- تقلل الضغط على DB بنسبة 80–95%
    
- تزود السرعة جدًا
    
- تخلي السيستم قابل للتوسع.
    

---

# 💥 خلاصة الفكرة

المطور المبتدئ يفكر:

> ازاي أقرأ من Database؟

المطور المحترف يفكر:

> ازاي أخلي Database تتسأل أقل عدد ممكن؟

وده الفرق الحقيقي في الـ Backend Engineering.
