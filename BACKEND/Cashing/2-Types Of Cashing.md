



# 🧠 أولًا: يعني إيه Types of Caching؟

👉 يعني **الكاش بيتحط فين؟ وبيشتغل إزاي؟**

---

# 🎯 أنواع الكاش (حسب المكان)

## 🟢 1. In-Memory Cache (جوا السيرفر)

👉 الكاش بيكون جوه نفس التطبيق (في الـ RAM)

---

## 💡 مثال:

في Java:

```java
Map<Long, User> cache = new HashMap<>();
```

---

## 🧠 بيشتغل إزاي؟

- أول request → يجيب من DB
    
- يحطه في memory
    
- بعد كدا → يرجع من الكاش
    

---

## ✅ مميزاته:

- سريع جدًا ⚡
    
- سهل
    

---

## ❌ عيوبه:

- لو السيرفر وقع → الكاش ضاع
    
- مش مناسب لو عندك أكتر من سيرفر
    

---

# 🟢 2. Distributed Cache 🔥

👉 الكاش بيكون في سيرفر خارجي (مش جوا التطبيق)

---

## 💡 مثال:

- Redis
    
- Memcached
    

---

## 🧠 بيشتغل إزاي؟

- كل السيرفرات بتكلم نفس الكاش
    
- الكاش مركزي
    

---

## ✅ مميزاته:

- مناسب للـ scaling
    
- shared بين كل السيرفرات
    

---

## ❌ عيوبه:

- أبطأ شوية من memory (network)
    
- محتاج setup
    

---

# 🟢 3. Client-Side Cache

👉 الكاش عند المستخدم (في المتصفح)

---

## 💡 مثال:

- Browser Cache
    
- Local Storage
    

---

## 🧠 بيستخدم في:

- الصور
    
- CSS / JS
    
- API responses أحيانًا
    

---

## ✅ مميزاته:

- بيقلل الضغط على السيرفر
    

---

## ❌ عيوبه:

- مش تحت سيطرتك 100%
    
- ممكن يبقى stale
    

---

# 🟢 4. CDN Cache 🌍

👉 الكاش بيتخزن في سيرفرات قريبة من المستخدم

---

## 💡 مثال:

- Cloudflare
    
- AWS CloudFront
    

---

## 🧠 بيشتغل إزاي؟

- المستخدم يطلب صورة
    
- CDN يديه نسخة قريبة منه
    

---

## ✅ مميزاته:

- سرعة عالية جدًا عالميًا
    
- يقلل latency
    

---

## ❌ عيوبه:

- مناسب للـ static content أكتر
    

---

# 🧩 مقارنة سريعة

|النوع|السرعة|الاستخدام|
|---|---|---|
|In-Memory|أسرع|Apps صغيرة|
|Distributed|سريع|Systems كبيرة|
|Client|سريع جدًا|Frontend|
|CDN|أسرع عالميًا|Static files|

---

# 🎯 الخلاصة

👉 الكاش مش نوع واحد  
👉 بتختار النوع حسب:

- حجم المشروع
    
- عدد السيرفرات
    
- نوع البيانات
    

---

# 💣 أهم نقطة (بتفرق في الشغل)

في المشاريع الكبيرة 👇

👉 بتستخدم **أكتر من نوع مع بعض** 😈

مثال:

- CDN → للصور
    
- Redis → للـ API
    
- Memory → للـ temporary data
