🌍 هنا يظهر مفهوم Region

يعني ايه Region ؟

الـ Region = منطقة جغرافية فيها داتا سنترز.

مثال:

ممكن يبقى عندهم:

Region في أوروبا

Region في أمريكا

Region في آسيا

Region في الشرق الأوسط


كل Region فيها:

👉 أكتر من Data Center


---

مثال حقيقي

شركة زي Amazon Web Services عندها Regions زي:

Frankfurt

London

Paris

Dubai

والسيرفر في أمريكا 🇺🇸

هيبقى بطيء ❌

لكن لو السيرفر في دبي 🇦🇪

هيبقى أسرع ✅

2️⃣ القوانين 📜

🧠 الخلاصة لحد دلوقتي

المفهوم	معناه

Data Center	مبنى فيه سيرفرات
Region	منطقة جغرافية فيها أكتر من Data Center

المحاضرة الجاية طبيعي تكمل بـ:

➡️ Availability Zones

(وده اللي جوه الـ Region)

جميل 👌 نكمل من حيث وقفنا…

إحنا وصلنا إن:

➡️ Region = منطقة جغرافية فيها أكتر من Data Center

لكن لسه في سؤال مهم 👇

> هل كل الداتا سنترز اللي جوه الـ Region بيبقوا كأنهم واحد؟



الإجابة ❌

وهنا يظهر أهم مفهوم بعد الـ Region 👇


---

🏢 Availability Zones (AZ)

يعني ايه Availability Zone ؟

الـ Availability Zone =

👉 داتا سنتر مستقلة جوه نفس الـ Region

لكن:

منفصلة كهرباء 🔌

منفصلة إنترنت 🌐

منفصلة تبريد ❄️


يعني لو واحدة وقعت…

التانية تفضل شغالة ✅


---

تخيل معايا كده 👇

Region = مدينة 🏙️
Availability Zones = مباني مختلفة داخل نفس المدينة


---

📌 مثال عملي

خلينا نقول:

عندك Region في دبي.

ممكن تبقى متقسمة كده:

AZ-1

AZ-2

AZ-3


كل واحدة = Data Center مستقل.

وده اللي بتعمله شركات زي:

Amazon Web Services

Microsoft Azure

Google Cloud



---

❓ ليه Availability Zones مهمة ؟

1️⃣ High Availability (استمرارية التشغيل)

لو حريق حصل في AZ ❌

السيستم شغال في AZ تانية ✅


---

2️⃣ Fault Isolation (عزل الأعطال)

يعني المشكلة متنتشرش.

زي السفينة اللي فيها حجرات…

لو حجرة غرقت مش السفينة كلها تغرق.


---

3️⃣ Disaster Recovery

لو حصل كارثة في داتا سنتر…

الابلكيشن يفضل شغال.

☁️ Cloud Service Models

يعني:

مستويات الخدمة اللي الكلاود بيوفرهالك


---

🧱 أول موديل: IaaS

Infrastructure as a Service

يعني:

👉 الكلاود بيديك "بنية تحتية"

وأنت تدير الباقي.

تاخد:

Server

Storage

Network


لكن أنت المسؤول عن:

OS

Runtime

Application

Data



---

مثال

سيرفر Virtual Machine من:

Amazon Web Services (EC2)

Microsoft Azure (Virtual Machines)


أنت كأنك استأجرت سيرفر.


---

تشبيه 🏠

IaaS = أرض فاضية

ابني بيتك بنفسك.


---

⚙️ تاني موديل: PaaS

Platform as a Service

هنا الكلاود يقولك:

👉 متشغلش بالك بالسيرفرات

أنا هدير:

OS

Runtime

Infrastructure


وأنت ركّز بس على:

✔️ الكود


---

مثال

لو رفعت API بدون ما تفكر في السيرفر

زي:

Azure App Services من Microsoft Azure



---

تشبيه 🏢

PaaS = شقة متشطبة

ادخل حط عفشك (الكود) وخلاص.


---

🧑‍💻 تالت موديل: SaaS

Software as a Service

هنا:

👉 أنت تستخدم برنامج جاهز

ولا تدير أي حاجة.


---

أمثلة

Gmail

Google Docs

Zoom


كلهم شغالين على الكلاود.

من مزودين زي:

Google Cloud



---

تشبيه 🍽️

SaaS = مطعم

تروح تاكل وخلاص.


---

🧠 مقارنة سريعة

الموديل	انت تدير ايه؟	مثال

IaaS	كل حاجة فوق السيرفر	VM
PaaS	الكود بس	Deploy API
SaaS	ولا حاجة	Gmail



---

🪜 ترتيب التحكم

IaaS → تحكم عالي  
PaaS → تحكم متوسط  
SaaS → تحكم قليل

🏗️ Cloud Deployment Models

---

1️⃣ Public Cloud

ده أشهر نوع.

يعني:

👉 تستخدم بنية تحتية مشتركة

مملوكة لشركات زي:

Amazon Web Services

Microsoft Azure

Google Cloud


وأنت مجرد عميل.


---

مثال

لما تعمل:

Deploy API على Azure

أو VM على AWS


ده اسمه:

✔️ Public Cloud


---

مميزاته

✅ أرخص
✅ سريع
✅ scalable
❌ تحكم أقل
❌ مشاركة موارد


---

تشبيه 🏢

زي شقة إيجار في عمارة.


---

2️⃣ Private Cloud

ده:

👉 كلاود خاص بشركة واحدة فقط

مش مشترك.

ممكن يبقى:

داخل الشركة نفسها

أو مستضاف لكن مخصص لها فقط



---

مثال

بنك 🏦
أو جهة حكومية

لازم البيانات تبقى معزولة 100%


---

مميزاته

✅ أمان أعلى
✅ تحكم كامل
❌ مكلف
❌ إدارة أصعب


---

تشبيه 🏠

فيلا خاصة.


---

3️⃣ Hybrid Cloud

ده خليط بين الاتنين 👇

✔️ Public
✔️ Private


---

مثال واقعي

شركة تخزن:

بيانات حساسة في Private

التطبيق نفسه في Public



---

مثال عملي

Backend:

DB → Private

API → Public



---

مميزاته

✅ مرونة
✅ أمان + توفير تكلفة
❌ تعقيد في الإدارة


---

تشبيه 🚗

عندك عربية خاصة + تستخدم Uber أحياناً.


---

Private	مخصص	أعلى	عالي
Hybrid	خليط	متوسط	عالي
