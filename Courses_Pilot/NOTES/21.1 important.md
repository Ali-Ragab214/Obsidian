بالضبط، لكن خلي بالك من فرق مهم جدًا بين **الأنواع البدائية (Primitive Types)** و **الـ Wrapper Classes**.

## Primitive Types

```java
int age;
boolean active;
double price;
```

القيم الافتراضية:

```java
int     => 0
long    => 0L
double  => 0.0
float   => 0.0f
boolean => false
char    => '\u0000'
```

مثال:

```java
public class User {

    private int age;
    private boolean active;
}
```

لو أنشأت Object:

```java
User user = new User();
```

هيبقى:

```text
age = 0
active = false
```

---

## Wrapper Classes

```java
Integer age;
Boolean active;
Long id;
Double price;
```

القيمة الافتراضية:

```java
null
```

مثال:

```java
public class User {

    private Integer age;
    private Boolean active;
}
```

هيبقى:

```text
age = null
active = null
```

---

## ليه ده مهم؟

بص على المثال ده:

```java
private boolean active;
```

ممكن يبقى:

```text
true
false
```

بس.

أما:

```java
private Boolean active;
```

ممكن يبقى:

```text
true
false
null
```

يعني 3 حالات.

---

## مثال من قواعد البيانات

لو عندك:

```java
@Column(nullable = false)
private boolean active;
```

فغالبًا `boolean` مناسب.

أما لو:

```java
@Column(nullable = true)
private Boolean approved;
```

فهنا `Boolean` منطقي لأن:

```text
true     => approved
false    => rejected
null     => not reviewed yet
```

---

## بالنسبة لموضوع `@Builder.Default`

لو عندك:

```java
@Builder
public class User {

    private Integer points = 0;
}
```

بدون:

```java
@Builder.Default
```

لما تعمل:

```java
User.builder().build();
```

قد تحصل على:

```text
points = null
```

وليس:

```text
points = 0
```

لأن Lombok Builder لا يستخدم القيمة الافتراضية المكتوبة في الـ field إلا إذا أضفت `@Builder.Default`.

---

### قاعدة احفظها

|النوع|القيمة الافتراضية|
|---|---|
|`int`|`0`|
|`long`|`0L`|
|`double`|`0.0`|
|`boolean`|`false`|
|`Integer`|`null`|
|`Long`|`null`|
|`Double`|`null`|
|`Boolean`|`null`|
|`String`|`null`|
|أي Object|`null`|

وده سبب إنك في مشاريع Spring/JPA هتشوف كتير:

```java
private Long id;
private Integer progress;
private Boolean active;
```

لأنهم أحيانًا يحتاجوا التفرقة بين **"القيمة صفر/False"** و **"لم يتم تعيين قيمة أصلًا (null)"**.
