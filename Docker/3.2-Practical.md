# 💥 المشكلة اللي Docker بيحلها (Real Problem)

أشهر جملة في البرمجة:

> ❌ “It works on my machine”

ليه بيحصل ده؟

علشان التطبيق بيعتمد على: 

- Node version
    
- .NET version
    
- Database version
    
- Environment variables
    
- OS libraries
    

لو نقلت المشروع لجهاز تاني:  
لازم تنزل كل ده بنفس الإصدارات… وغالباً بيحصل مشاكل.

## الحل

نحط **كل البيئة كاملة** داخل صندوق اسمه Container.

👉 نفس البيئة = نفس التشغيل = نفس النتيجة في أي جهاز.

---

# 🐳 ما هو Docker؟  

Docker هو Platform لتشغيل التطبيقات داخل **Containers** (بيئة معزولة).

Container يحتوي على:

- التطبيق
    
- dependencies
    
- runtime
    
- system libraries
    
- environment variables
    

👉 يعني نسخة مصغرة من جهازك.

---

# 🧠 Core Concepts (أهم جزء)

## 1️⃣ Image = Blueprint (زي Class)

صورة جاهزة نعمل منها Containers.

أمثلة Images جاهزة:

- nginx
    
- node
    
- postgres
    
- ubuntu
    

الصورة **مش بتشتغل** لوحدها.

نجيبها من:  
Docker Hub (registry)

```bash
docker pull nginx
```

---

## 2️⃣ Container = Running Instance (زي Object)

نسخة شغالة من Image.

نقدر:

- start
    
- stop
    
- pause
    
- delete
    

تشغيل container:

```bash
docker run nginx
```

لو الصورة مش موجودة locally → Docker هيعمل Pull تلقائي.

# 📦 أهم Commands لإدارة Containers

## عرض الكونتينرز

```bash
docker ps
```

Running containers فقط.

```bash
docker ps -a
```

كل الكونتينرز حتى المتوقفة.

---

## تشغيل container في الخلفية

```bash
docker run -d nginx
```

`-d` = Detached mode  
يعني يرجعلك التيرمنال.

---

## تشغيل مع Ports

```bash
docker run -d -p 8080:80 nginx
```

معناها:

- 8080 → جهازك
    
- 80 → داخل الكونتينر
    

الـ browser يكلم جهازك → Docker يحول الطلب للكونتينر.

---

## تسمية الكونتينر

```bash
docker run -d -p 8080:80 --name my-nginx nginx
```

---

## إيقاف الكونتينر

```bash
docker stop my-nginx
```

## حذف الكونتينر

```bash
docker rm my-nginx
```

# 🧱 Dockerfile (أهم نقطة)

Dockerfile = Script بنكتب فيه خطوات بناء الـ Image.

## مثال Node بسيط

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY . .
RUN npm install
EXPOSE 8081
CMD ["node", "app.js"]
```

## شرح كل Instruction

### 🔹 FROM

اختيار Base Image.

```dockerfile
FROM node:20-alpine
```

مش بنبدأ من صفر.  
بنستخدم image جاهزة ونبني فوقها.

---

### 🔹 WORKDIR

تحديد فولدر العمل داخل الكونتينر.

```dockerfile
WORKDIR /app
```

---

### 🔹 COPY

نسخ الملفات من جهازك للكونتينر.

```dockerfile
COPY . .
```

---

### 🔹 RUN

أوامر وقت **بناء image**.

```dockerfile
RUN npm install
```

---

### 🔹 EXPOSE

إخبار Docker بالـ port.

```dockerfile
EXPOSE 8081
```

---

### 🔹 CMD

الأمر اللي يشتغل عند تشغيل الكونتينر.

```dockerfile
CMD ["node", "app.js"]
```

---

# 🔨 بناء Image من Dockerfile

```bash
docker build -t my-node-app .
```

`-t` = tag (اسم الصورة)

# ▶️ تشغيل Image

```bash
docker run -p 8081:8081 --name nodeApp my-node-app
```

# 💾 أهم مفهوم: Volumes (الداتا)

⚠️ أخطر غلطة:  
تحط الداتا داخل الكونتينر.

ليه؟  
لأن الكونتينر **ephemeral**  
لو اتحذف → الداتا تضيع.

## الحل = Volumes

نخزن الداتا خارج الكونتينر.

```bash
docker run -v mydata:/var/lib/postgresql/data postgres
```

الداتا تبقى على جهازك والكونتينر يستخدمها.

# 🧩 Docker Compose (تشغيل النظام كامل)

مشروع حقيقي فيه:

- backend
    
- database
    
- redis
    
- nginx
    

تشغيلهم بأوامر كثيرة = كابوس 😅

## الحل → docker-compose.yml

### مثال كامل Node + Postgres

```yaml
version: "3.9"

services:
  app:
    build: .
    ports:
      - "3000:3000"
    depends_on:
      - db

  db:
    image: postgres
    environment:
      POSTGRES_PASSWORD: 123456
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

---

## تشغيل المشروع كله

```bash
docker compose up -d
```

إيقاف:

```bash
docker compose down
```
