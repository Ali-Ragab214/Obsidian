## Docker & Dockerfile — الشرح من الصفر

---

## 1. المشكلة اللي Docker بيحلها

تخيل السيناريو ده:

```
انت شغال على الـ app بتاعك على جهازك
كل حاجة شغالة تمام ✅

بعتها للـ server أو لزميلك
مشتغلتش ❌

"but it works on my machine!"
```

السبب إن الـ server عنده:

- Java version مختلفة
- PostgreSQL version مختلفة
- OS مختلف
- Environment variables مختلفة

---

## 2. الحل — Docker

فكر في Docker كـ **صندوق معزول** فيه كل حاجة الـ app محتاجها:

```
┌─────────────────────────────┐
│         Container           │
│                             │
│  ┌─────────────────────┐   │
│  │   App بتاعك         │   │
│  ├─────────────────────┤   │
│  │   Java 21           │   │
│  ├─────────────────────┤   │
│  │   Dependencies      │   │
│  ├─────────────────────┤   │
│  │   Config            │   │
│  └─────────────────────┘   │
│                             │
└─────────────────────────────┘
```

الصندوق ده بيشتغل **نفس بالظبط** على أي machine ✅

---

## 3. الـ Dockerfile — إيه ده؟

ده ملف بيقول لـ Docker **ازاي يبني الصندوق ده**

```
Dockerfile = وصفة الطبخ
Image = الأكلة الجاهزة
Container = الطبق اللي بتاكل منه
```

---

## 4. Dockerfile لمشروعك

اعمل file اسمه `Dockerfile` في **root المشروع** (نفس مستوى `pom.xml`):

```dockerfile
# ─── Stage 1: Build ───────────────────────────────
# بنستخدم image فيها Java + Maven عشان نعمل build
FROM maven:3.9-eclipse-temurin-21 AS build

# بنحدد الـ working directory جوه الـ container
WORKDIR /app

# بننسخ الـ pom.xml الأول عشان نحمل الـ dependencies
COPY pom.xml .

# بنحمل كل الـ dependencies (بيتعمل cache لو pom.xml ما اتغيرش)
RUN mvn dependency:go-offline

# بننسخ باقي الـ source code
COPY src ./src

# بنعمل build وبنشيل الـ tests عشان أسرع
RUN mvn clean package -DskipTests


# ─── Stage 2: Run ─────────────────────────────────
# بنستخدم image أصغر بس فيها Java عشان نشغل الـ app
FROM eclipse-temurin:21-jre-alpine

WORKDIR /app

# بننسخ الـ jar من الـ Stage 1 بس
COPY --from=build /app/target/*.jar app.jar

# بنفتح الـ port 8080
EXPOSE 8080

# الأمر اللي بيشغل الـ app
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## 5. شرح كل سطر

```dockerfile
FROM maven:3.9-eclipse-temurin-21 AS build
```

> جيب image فيها Maven و Java 21 واسمها `build`

```dockerfile
WORKDIR /app
```

> اشتغل في folder اسمه `/app` جوه الـ container

```dockerfile
COPY pom.xml .
RUN mvn dependency:go-offline
```

> انسخ الـ pom.xml وحمّل الـ dependencies لو الـ pom.xml ما اتغيرش → الـ Docker مش هيعمل ده تاني (cache) ✅

```dockerfile
COPY src ./src
RUN mvn clean package -DskipTests
```

> انسخ الـ كود وابني الـ jar

```dockerfile
FROM eclipse-temurin:21-jre-alpine
```

> ابدأ image جديدة أصغر بكتير — بس فيها Java runtime مش Maven

```dockerfile
COPY --from=build /app/target/*.jar app.jar
```

> انسخ الـ jar بس من الـ stage الأول — مش محتاج الـ source code

```dockerfile
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

> افتح الـ port وشغّل الـ app

## 6. الـ docker-compose.yml

لأن الـ app بتاعك محتاجة PostgreSQL كمان، بنستخدم `docker-compose`:

اعمل file اسمه `docker-compose.yml` جنب الـ `Dockerfile`:

```yaml
version: '3.8'

services:

  # ─── PostgreSQL ───────────────────────────────
  db:
    image: postgres:16-alpine
    container_name: skillhub_db
    environment:
      POSTGRES_DB: learning_academy
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data  # عشان الـ data ما تتمسحش

  # ─── Spring Boot App ──────────────────────────
  app:
    build: .                          # ابني من الـ Dockerfile الموجود هنا
    container_name: skillhub_app
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/learning_academy
      SPRING_DATASOURCE_USERNAME: postgres
      SPRING_DATASOURCE_PASSWORD: postgres
    depends_on:
      - db                            # استنى الـ DB تشتغل الأول

volumes:
  postgres_data:
```

## 8. ازاي تشغله؟

```bash
# ابني وشغّل كل حاجة
docker-compose up --build

# أو في الـ background
docker-compose up --build -d

# وقّف كل حاجة
docker-compose down

# وقّف وامسح الـ data
docker-compose down -v
```

## 10. خلف الكواليس لما تعمل `docker-compose up`

```
1. Docker يقرأ docker-compose.yml
        │
        ▼
2. يعمل build للـ Dockerfile
        │
        ▼
3. يشغل PostgreSQL container
        │
        ▼
4. يستنى الـ DB تبقى ready
        │
        ▼
5. يشغل Spring Boot container
        │
        ▼
6. Flyway بيشتغل وبينفذ الـ migrations
        │
        ▼
7. الـ App شغال على localhost:8080 ✅
```
