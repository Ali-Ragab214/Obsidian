# أولاً: ما هو RAG

## Retrieval-Augmented Generation (RAG)

**RAG** هو تقنية في الذكاء الاصطناعي تسمح للموديل بالوصول إلى **بيانات خارجية أثناء توليد الإجابة**.

بمعنى بسيط:

بدل أن يعتمد الموديل فقط على المعلومات التي تعلمها أثناء التدريب،  
يمكنه **البحث في قاعدة بيانات أو مستندات** ثم يستخدم هذه المعلومات ليعطي إجابة أدق.

### الفكرة الأساسية

عند سؤال الموديل:

1️⃣ يتم **البحث عن معلومات مرتبطة بالسؤال** في قاعدة بيانات  
2️⃣ يتم **إرسال هذه المعلومات مع السؤال للموديل**  
3️⃣ الموديل يولد الإجابة باستخدام **السؤال + المعلومات المسترجعة**

---

## مثال بسيط

تخيل أنك عملت Chatbot لشركة.

العميل يسأل:

> ما سعر الاشتراك في الباقة الذهبية؟

بدل أن يكون السعر داخل الموديل نفسه،  
الـ RAG يقوم بـ:

1. البحث في قاعدة بيانات الشركة
    
2. إيجاد الملف الذي يحتوي السعر
    
3. إرسال المعلومات للموديل
    
4. الموديل يولد الإجابة
    

النتيجة:

الموديل يعطي **معلومات حديثة ودقيقة**.

---

# ثانياً: الفرق بين RAG و Fine-Tuning

## 1️⃣ RAG

الفكرة:

الموديل **يبحث عن المعلومات أثناء الإجابة**.

الخصائص:

- يستخدم **مصادر بيانات خارجية**
    
- يمكنه جلب **معلومات حديثة**
    
- لا يغير الموديل نفسه
    
- يعمل أثناء **Inference time**
    يبحث عن الداتا اثناء تجهيز الريسبونس وبجيبيها من مصادر خارجيه 

مثال:

ChatGPT يبحث في:

- PDF
    
- Database
    
- API
    
- Documents
    

---

## 2️⃣ Fine-Tuning

الفكرة:

تقوم **بإعادة تدريب الموديل على بياناتك الخاصة**.

بمعنى أنك تعطيه Dataset خاصة بك مثل:

```
Question: What is our refund policy?
Answer: Our refund policy allows returns within 30 days.
```

الموديل يتعلم منها ويصبح **متخصص في هذا المجال**.

الخصائص:

- المعرفة تصبح **داخل الموديل نفسه**
    
- يعطي **إجابات ثابتة ومتخصصة**
    
- لا يستطيع معرفة معلومات جديدة إلا إذا **أعدت تدريبه**
    

---

# الفرق بين RAG و Fine-Tuning (جدول مهم)

|Feature|RAG|Fine-Tuning|
|---|---|---|
|مصدر المعلومات|مصادر خارجية|داخل الموديل|
|تحديث المعلومات|فوري|يحتاج إعادة تدريب|
|التكلفة|أقل|أعلى|
|المرونة|عالية|أقل|
|الاستخدام|البحث في مستندات|تدريب موديل متخصص|

# ثالثاً: RAG Data Pipeline Flow

هذا يشرح **كيف يتم تجهيز البيانات لتستخدم في RAG**.

الخطوات:

## 1️⃣ إدخال المستندات

يتم إدخال البيانات مثل:

- PDF
    
- Word
    
- Web pages
    
- Text files
    

إلى **Data Pipeline**.

---

## 2️⃣ معالجة المستند

الـ pipeline تقوم بعدة عمليات:

### a) Chunking

يتم تقسيم المستند إلى أجزاء صغيرة تسمى:

**Chunks**

مثال:

مقال من 1000 كلمة  
يتم تقسيمه إلى:

```
chunk1
chunk2
chunk3
```

السبب:

الموديلات تعمل أفضل مع **نصوص صغيرة**.

---

### b) Enrich Chunks

يتم إضافة **Metadata** لكل chunk.

مثل:

- title
    
- summary
    
- keywords
    

مثال:

```
Title: Docker Basics
Keywords: containers, docker, images
Summary: Introduction to docker
```

---

### c) Embedding Chunks

يتم تحويل كل chunk إلى **Vector** باستخدام **Embedding Model**.

مثال:

النص:

```
Docker is a container platform
```

يتحول إلى:

```
[0.23, 0.81, 0.12, 0.44, ...]
```

هذه الأرقام تسمى:

**Embedding Vector**

---

### d) Persist Chunks

يتم تخزين الـ vectors في:

**Vector Database**

مثل:

- Pinecone
    
- Weaviate
    
- Chroma
    
- Milvus
    
- FAISS

# رابعاً: ما هي Embeddings

## تعريف Embeddings

**Embeddings** هي طريقة لتحويل النص إلى **أرقام (vectors)**.

الهدف:

جعل الكمبيوتر يفهم **معنى الكلمات**.

بدل:

```
king
queen
apple
```

تصبح:

```
king   → [0.21, 0.44, 0.91 ...]
queen  → [0.22, 0.45, 0.90 ...]
apple  → [0.91, 0.12, 0.33 ...]
```

نلاحظ أن:

king و queen قريبين من بعض  
لأن معناهم متشابه.

---

## لماذا نستخدم Embeddings

لكي نستطيع:

- البحث الدلالي (Semantic search)
    
- مقارنة النصوص
    
- إيجاد النصوص المتشابهة
    

---

## مثال

لو المستخدم سأل:

> How to run docker container?

النظام يبحث عن **chunks التي لها معنى قريب** من السؤال.

ليس بالضرورة نفس الكلمات.

---

# خامساً: Vector Databases

## ما هي Vector Database

هي قاعدة بيانات تخزن **البيانات على شكل vectors**.

بدل:

```
text
```

تخزن:

```
[0.34, 0.88, 0.12 ...]
```

---

## وظيفتها

عند السؤال:

1️⃣ تحويل السؤال إلى vector  
2️⃣ البحث عن أقرب vectors  
3️⃣ استرجاع النصوص المرتبطة

---

## مثال

السؤال:

```
How to build docker image?
```

الـ vector database ترجع:

```
chunk1: Docker build command
chunk2: Dockerfile explanation
```

ثم يتم إرسالها للموديل.

---

# سادساً: RAG Flow الكامل

العملية بالكامل تكون كالتالي:

### Step 1

المستخدم يسأل سؤال.

```
User Question
```

---

### Step 2

تحويل السؤال إلى **Embedding**

---

### Step 3

البحث في **Vector Database**

---

### Step 4

استرجاع أفضل **Chunks**

---

### Step 5

إرسال:

```
Question + Retrieved Chunks
```

إلى LLM

---

### Step 6

الموديل يولد الإجابة.

---

## الشكل النهائي

```
User Question
      ↓
Embedding
      ↓
Vector Database Search
      ↓
Retrieve Relevant Chunks
      ↓
Send to LLM
      ↓
Generated Answer
```
