# 🧠 أولًا: يعني ايه Method Overriding؟

لما **Child class** يكتب نفس method موجودة في **Parent class** لكن بسلوك مختلف.

مثال:

```java
class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Bark");
    }
}
```

# 1️⃣ Return Type في Overriding

## مثال مهم:

```java
class Parent { 
   double getValue()
    {        return 10.5;    }}
class Child extends Parent {    
@Override    int getValue() 
{ // ❌ ERROR        return 10;    }}
```



```java
class Parent {
    Number getValue() {
        return 10.5;
    }
}

class Child extends Parent {
    @Override
    Integer getValue() { // ✔️ valid
        return 10;
    }
}
```
## القاعدة:

✔️ ممكن تغيّر الـ return type  
❗ لكن بشرط يكون **Covariant return type**

يعني:

> لازم يكون نفس النوع أو subtype منه

---

## مثال صحيح ✔️

```java
class Animal {}

class Dog extends Animal {}

class Parent {
    Animal get() {
        return new Animal();
    }
}

class Child extends Parent {
    @Override
    Dog get() {   // valid
        return new Dog();
    }
}
```

💡 ليه ده صح؟  
لأن Dog → subclass من Animal

---

## مثال خطأ ❌

```java
class Child extends Parent {
    @Override
    String get() {  // ERROR
        return "test";
    }
}
```

---

# 🧠 الخلاصة:

✔️ نفس النوع أو subtype  
❌ مش أي نوع مختلف

# 2️⃣ Access Modifiers

## القاعدة:

✔️ تقدر توسّع الصلاحية  
❌ لكن لا تقدر تضيقها

---

## ترتيب الصلاحيات:
```
private < default < protected < public
```

```text
private < default < protected < public
```

---

## مثال صحيح ✔️

```java
class Parent {
    protected void show() {}
}

class Child extends Parent {
    @Override
    public void show() {}  // valid (wider)
}
```

---

## مثال خطأ ❌

```java
class Child extends Parent {
    @Override
    private void show() {}  // ERROR (narrower)
}
```

---

# 🧠 الخلاصة:

✔️ ممكن تخليها public بدل protected  
❌ ممنوع تقلل الصلاحية

---

# 3️⃣ Exceptions in Overriding

## القاعدة:

✔️ تقدر ترمي نفس exception أو أقل  
❌ ممنوع ترمي checked exception أكبر أو جديدة

---

## مثال صحيح ✔️

```java
class Parent {
    void read() throws IOException {}
}

class Child extends Parent {
    @Override
    void read() throws IOException {} // same
}
```

أو:

```java
class Child extends Parent {
    @Override
    void read() {} // no exception (allowed)
}
```

---

## مثال خطأ ❌

```java
class Child extends Parent {
    @Override
    void read() throws Exception {} // ERROR (broader)
}
```

---

# 🧠 الخلاصة:

✔️ نفس exception  
✔️ أو أضيق (subclass)  
❌ مش أوسع

---

# 🎯 الإجابة الجاهزة للانترفيو

لو سألوك، تقول:

> In method overriding:
> 
> - Return type can be the same or a covariant type (subclass of the original return type).
>     
> - Access modifier cannot be more restrictive; it can be same or more permissive.
>     
> - Checked exceptions must be same or narrower; you cannot throw broader checked exceptions.
>
