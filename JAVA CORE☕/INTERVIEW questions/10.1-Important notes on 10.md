when u choose aggregation over composition ? 
> I would choose Aggregation when I need loose coupling, flexibility, and better testability.  
> In Aggregation, the object is passed from outside, which works well with Dependency Injection and makes the system easier to maintain and test.

وبعدين تكمل:

> On the other hand, I would choose Composition when the child object strongly belongs to the parent object and cannot exist independently from it.


---
> Inheritance models “what an object IS”, while Composition/Aggregation model “what an object HAS”.
### Composition — الـ Engine جزء من الـ Car

```java
class Engine {
    String type;

    Engine(String type) {
        this.type = type;
    }

    void start() {
        System.out.println(type + " Engine started");
    }
}

class Car {
    String model;
    Engine engine;  // جزء من الـ Car

    Car(String model) {
        this.model = model;
        this.engine = new Engine("V8");  // اتعمل جوّا ✅
    }

    void drive() {
        engine.start();
        System.out.println(model + " is moving");
    }
}

public class Main {
    public static void main(String[] args) {
        Car car = new Car("BMW");
        car.drive();

        // لو Car اتحذف → Engine اتحذف معاه
        // Engine مش موجود من غير Car
    }
}
```

### Aggregation — الـ Driver عنده Car بس مستقل عنها

```java
class Car {
    String model;

    Car(String model) {
        this.model = model;
    }
}

class Driver {
    String name;
    Car car;  // عنده Car بس مش جزء منه

    Driver(String name, Car car) {
        this.name = name;
        this.car = car;  // جاي من برّا ✅
    }

    void drive() {
        System.out.println(name + " is driving " + car.model);
    }
}

public class Main {
    public static void main(String[] args) {
        Car car = new Car("BMW");       // اتعمل برّا
        Driver driver = new Driver("Ahmed", car);  // اتبعت من برّا

        driver.drive();

        // لو Driver اتحذف → Car فاضلة موجودة ✅
    }
}
```

## الـ Dependency Injection بيندرج تحت إيه؟

**Aggregation** ✅

لأن الـ DI بيعتمد على إنك **تبعت الـ Object من برّا** بدل ما تعمله جوّا:

```java
// ❌ Composition — مش DI
class OrderService {
    PaymentService payment = new PaymentService();  // عامله جوّا
}

// ✅ Aggregation / DI — بييجي من برّا
class OrderService {
    PaymentService payment;

    OrderService(PaymentService payment) {  // Spring بيحقنه
        this.payment = payment;
    }
}
```

---

### ليه الـ DI أحسن من Composition هنا؟

```
Composition → OrderService مرتبط بـ PaymentService للأبد
            → مش تقدر تغيره في الـ Testing
            → Tight Coupling ❌

DI (Aggregation) → تبعت أي Implementation
                 → في الـ Testing تبعت Mock
                 → Loose Coupling ✅
```
