تمام، هنبدأ **من الصفر** ونبني الموضوع واحدة واحدة لحد ما نوصل لسؤال الإنترفيو:

> **Can an abstract class have a constructor? When would it be called?**

---

# 1. يعني إيه Abstract Class؟

الـ **abstract class** هي class بنستخدمها كـ **base class** للكلاسات اللي هتورث منها.

يعني أنا بقول:

> "أنا عندي concept عام، ومش عايز حد يعمل منه object مباشرة، لكن عايز الكلاسات التانية تورث منه."

مثال:

```java
abstract class Animal {

    abstract void makeSound();

    void eat() {
        System.out.println("Eating...");
    }
}
```

هنا `Animal` عبارة عن **abstract class**.

ومنعملش:

```java
Animal animal = new Animal(); // ❌
```

لأن الـ abstract class **مينفعش نعمل منها object مباشرة**.

لكن نقدر نعمل class يرث منها:

```java
class Dog extends Animal {

    @Override
    void makeSound() {
        System.out.println("Woof");
    }
}
```

وبعدين:

```java
Dog dog = new Dog(); // ✅
```

---

# 2. ليه أصلًا بنستخدم Abstract Class؟

عشان نعمل **common structure + common behavior** للكلاسات اللي هتورث منها.

مثلاً:

```java
abstract class Animal {

    String name;

    void eat() {
        System.out.println("Eating...");
    }

    abstract void makeSound();
}
```

كل الحيوانات:

- عندها `name`
    
- ممكن تاكل
    
- لكن طريقة إصدار الصوت مختلفة.
    

فأحط الـ common behavior في الـ abstract class:

```java
void eat()
```

وأسيب الـ behavior المختلف للـ subclasses:

```java
abstract void makeSound();
```

---

# 3. هل الـ Abstract Class ممكن تحتوي على Constructor؟

**أيوه طبعًا.** ✅

ودي نقطة مهمة جدًا في الإنترفيو.

```java
abstract class Animal {

    String name;

    Animal(String name) {
        this.name = name;
    }

    abstract void makeSound();
}
```

رغم إننا **مينفعش نعمل object من `Animal` مباشرة**، إلا إن الـ abstract class ممكن يكون عندها constructor.

---

# 4. طب الـ Constructor بتاع Abstract Class بيتنادي إمتى؟

هنا بقى السؤال الأساسي.

لما تعمل object من subclass:

```java
Dog dog = new Dog("Bobby");
```

الـ `Animal` constructor **بيتـcall الأول** أثناء إنشاء الـ `Dog`.

يعني الـ flow بيكون:

```text
new Dog()
   ↓
Animal constructor
   ↓
Dog constructor
   ↓
Dog object created
```

مثال كامل:

```java
abstract class Animal {

    String name;

    Animal(String name) {
        System.out.println("Animal constructor");
        this.name = name;
    }

    abstract void makeSound();
}
```

```java
class Dog extends Animal {

    Dog(String name) {
        super(name);
        System.out.println("Dog constructor");
    }

    @Override
    void makeSound() {
        System.out.println("Woof");
    }
}
```

لما تعمل:

```java
Dog dog = new Dog("Bobby");
```

الـ output:

```text
Animal constructor
Dog constructor
```

---

# 5. ليه الـ Parent Constructor بيتنفذ أصلًا؟

لأن الـ `Dog` **is an Animal**، والجزء الخاص بالـ `Animal` لازم يتم تهيئته الأول.

يعني الـ object في الحقيقة بيحتوي على جزء inherited من الـ parent:

```text
Dog Object
│
├── Animal part
│   └── name
│
└── Dog part
```

فلازم الأول نعمل initialization للـ `Animal part`.

وده اللي بيحصل عن طريق:

```java
super(name);
```

ولو مفيش `super()` مكتوبة، Java بتحاول تضيف **implicit `super()`** تلقائيًا، بشرط إن الـ parent عنده no-args constructor.

---

# 6. نقطة مهمة جدًا في الإنترفيو

السؤال:

> **Can you instantiate an abstract class?**

الإجابة:

> **No, you cannot directly instantiate an abstract class. However, its constructor is still called when an instance of a concrete subclass is created.**

يعني:

```java
Animal a = new Animal(); // ❌
```

لكن:

```java
Dog d = new Dog(); // ✅
```

وأثناء `new Dog()`:

```text
Animal constructor → Dog constructor
```

---

# 7. طيب إمتى أستخدم Constructor في Abstract Class؟

لما يكون عندي **common state** محتاج كل الـ subclasses تهيئه.

مثلاً:

```java
abstract class Employee {

    protected String name;
    protected double salary;

    Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }
}
```

وبعدين:

```java
class Developer extends Employee {

    Developer(String name, double salary) {
        super(name, salary);
    }
}
```

هنا بدل ما كل subclass يكرر initialization بتاع:

```java
this.name = name;
this.salary = salary;
```

الـ abstract class مسؤولة عن تهيئة الـ common state.

---

# الخلاصة اللي تتحفظ 🔥

**Abstract class:**

> A class that cannot be instantiated directly and is typically used as a base class for subclasses.

**Can it have a constructor?**

> **Yes.**

**When is its constructor called?**

> **When a concrete subclass object is created, before the subclass constructor executes.**

**Why?**

> To initialize the state inherited from the abstract parent class.

والـ flow احفظه:

```text
new ConcreteClass()
       ↓
Abstract Class Constructor
       ↓
Concrete Class Constructor
       ↓
Object Ready
```

وده بالظبط سبب إن وجود constructor في `abstract class` **مش تناقض** مع إنك مينفعش تعمل منها object مباشرة.
