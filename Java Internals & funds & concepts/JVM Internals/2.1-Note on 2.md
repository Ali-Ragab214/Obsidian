بالظبط، لكن خليني أدققها شوية عشان دي نقطة بيغلط فيها ناس كتير.

لما تكتب:

```java
String name = "Ahmed";
```

فيه 3 حاجات بتحصل:

### 1. المتغير المرجعي `name`

```java
name
```

ده Local Variable.

بيتخزن في الـ **Stack** (لو جوه Method).

---

### 2. الـ String Object

```java
"Ahmed"
```

الـ String Object نفسه بيتخزن في الـ **Heap**.

لكن مش في أي حتة في الـ Heap...

بيتخزن في منطقة خاصة اسمها:

```text
String Pool
```

والـ String Pool جزء من الـ Heap.

---

### 3. الـ Reference

المتغير:

```java
name
```

جواه Address بيشاور على:

```java
"Ahmed"
```

اللي موجودة في الـ Heap.

فالشكل يبقى:

```text
STACK
┌──────┐
│ name │ ───────────────┐
└──────┘                │
                        ▼
HEAP (String Pool)
┌──────────┐
│ "Ahmed"  │
└──────────┘
```

---

### مثال مهم

```java
String s1 = "Ahmed";
String s2 = "Ahmed";
```

هنا الـ JVM مش هتعمل Object جديد.

هيستخدموا نفس الـ String الموجودة في الـ Pool.

```text
STACK

s1 ───┐
       ├────► "Ahmed"
s2 ───┘
```

عشان كده:

```java
System.out.println(s1 == s2);
```

النتيجة:

```java
true
```

---

### لكن لو عملت

```java
String s1 = new String("Ahmed");
String s2 = new String("Ahmed");
```

هنا أنت غصبت JVM تعمل Object جديد كل مرة.

```text
HEAP

Object1 -> "Ahmed"
Object2 -> "Ahmed"
```

فـ:

```java
s1 == s2
```

هيبقى:

```java
false
```

لأن كل واحد بيشاور على Object مختلف.

---

### الخلاصة

في السطر:

```java
String name = "Ahmed";
```

✅ `name` (الـ reference) → في Stack

✅ `"Ahmed"` (الـ object) → في Heap داخل String Pool

✅ `name` بيحتفظ بعنوان الـ object الموجود في الـ Heap
