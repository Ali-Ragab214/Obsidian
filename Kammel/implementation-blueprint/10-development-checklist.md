## 1. قائمة التحقق اليومية لأي طلب دمج (Daily PR Developer Checklist)

قبل فتح أي Pull Request أو دمج كود ميزة جديدة في الفرع الرئيسي:
- [ ] **عزل المستأجر:** هل كل جدول أو كيان جديد يمتلك عمود `org_id UUID` ومشمول بسياسات الـ RLS؟
- [ ] **الدقة المالية:** هل جميع المبالغ النقدية معرفة كـ `Long` أو `BIGINT` بالقروش وخالية تماماً من `float` أو `double`؟
- [ ] **الأمان والصلاحيات:** هل جميع دوال الـ Service محمية بـ `@PreAuthorize` ومفحوصة الصلاحيات؟
- [ ] **عقود البيانات:** هل تم استخدام DTOs مستقلة لمدخلات ومخرجات الـ API مع استبعاد كيانات الـ JPA من طبقة العرض؟
- [ ] **التحقق من المدخلات:** هل تم وضع قيود Bean Validation وفحص أرقام الهواتف المصرية بـ `@ValidPhone`؟
- [ ] **التسجيل والخصوصية:** هل سجلات الـ Logging خالية تماماً من أرقام الهواتف والبيانات الشخصية الحساسة (PII)؟
- [ ] **اختبارات الوحدة والتكامل:** هل تم كتابة اختبارات منطق العمل واختبار عزل المستأجرين عبر Testcontainers؟
- [ ] **حدود الموديولات:** هل تم التحقق من نجاح اختبار `Spring Modulith` وعدم وجود اعتمادات دائرية؟

## 3. قائمة متابعة المرحلة 1: النواة التأسيسية والأمان وعزل المستأجرين (Weeks 1 to 3)

### البنية التحتية والبيئة المشتركة (`shared/`):
- [ ] إعداد مشروع Spring Boot 3 مع Java 21 وملف إدارة الاعتماديات (Maven/Gradle).
- [ ] تجهيز ملف `docker-compose.yml` لتشغيل PostgreSQL 16 محلياً مع مساحة تخزين دائمة.
- [ ] إعداد مسار التكامل المستمر GitHub Actions (`.github/workflows/ci.yml`).
- [ ] كتابة الكيان الأب المشترك `BaseEntity` والواجهة `TenantScoped`.
- [ ] كتابة أطر الاستجابات العامة: `ApiResponse<T>`, `PageResponse<T>`, و `ErrorResponse`.
- [ ] كتابة كلاس معالجة الاستثناءات المركزي `GlobalExceptionHandler` وتغطية استثناءات التحقق وحالات التعارض.
- [ ] كتابة أدوات العمليات الحسابية والزمنية: `MoneyUtil` (قروش/جنيهات), `PhoneUtil`, و `DateUtil`.
- [ ] كتابة المدقق المخصص `@ValidPhone` لفحص أرقام الهواتف المصرية.

### ميزات `tenancy` و `identity` وسياسات الأمان:
- [ ] كتابة ملفات هجرات Flyway: `V1__create_organizations_and_branches.sql` و `V2__create_users.sql`.
- [ ] إعداد سياق المستأجر `TenantContext` بالـ ThreadLocal مع تنظيفه في فلتر `TenantFilter`.
- [ ] برمجة فلتر ضبط جلسة المستأجر في قاعدة البيانات: `SET LOCAL app.current_org = ?`.
- [ ] تفعيل وتطبيق سياسات PostgreSQL Row-Level Security (RLS) على جميع جداول المستأجرين.
- [ ] تنفيذ خدمة المصادقة `AuthService` وتوليد توكنات JWT وتدوير الـ Refresh Tokens.
- [ ] تشفير كلمات المرور باستخدام BCrypt (Work Factor 12).
- [ ] بناء وتأمين Endpoints المصادقة: `/api/v1/auth/login`, `/api/v1/auth/refresh`, و `/api/v1/auth/logout`.
- [ ] **نقطة التحقق 1:** تشغيل جناح اختبارات عزل المستأجرين الكامل عبر Testcontainers والتأكد من نجاحه 100%.

## 4. قائمة متابعة المرحلة 2: عقود العضوية والمنظومة المالية (Weeks 4 to 6)

### شريحة الأعضاء (`features/member`):
- [ ] كتابة ملف Flyway: `V3__create_members.sql` مع فهارس مركبة `(org_id, phone)`.
- [ ] بناء كيان `Member` وواجهة `MemberRepository` مع دعم التصفح والبحث المرن.
- [ ] تطبيق الحذف المرن (Soft Delete) عبر حقل `deleted_at`.
- [ ] كتابة `MemberService` ومعالجة تسجيل وتعديل واسترجاع الأعضاء.
- [ ] بناء خدمة استيراد الإكسيل `MemberImportService` عبر Apache POI مع التحقق من الهواتف وتقديم تقرير بالأخطاء.
- [ ] ربط Endpoints الأعضاء: `POST /api/v1/members`, `GET /api/v1/members`, و `POST /api/v1/members/import`.

### شريحة الباقات وعقود الاشتراكات (`features/plan` & `features/subscription`):
- [ ] كتابة ملفات Flyway: `V4__create_membership_plans.sql`, `V5__create_subscriptions.sql`, و `V6__create_subscription_events.sql`.
- [ ] بناء كيان `MembershipPlan` وتخزين السعر بالقرش ومدة العقد وأيام التجميد والسماح.
- [ ] بناء كيان `Subscription` وتطبيق لقطة السعر الثابتة `price_minor_snapshot`.
- [ ] بناء آلة الحالات (State Machine) مع التحقق من صحة التحولات عبر `SubscriptionStateChecker`.
- [ ] تطبيق منطق التجديد الذكي (تمديد تاريخ الانتهاء دون ضياع أيام العضو).
- [ ] تطبيق منطق التجميد (Freeze) وفك التجميد وتمديد الصلاحية بعدد الأيام الفعلية.
- [ ] تسجيل كل حركة في سجل أحداث الاشتراك غير القابل للتعديل `SubscriptionEvent`.
- [ ] ربط Endpoints الاشتراكات: الإنشاء، التجديد، والتجميد.

### شريحة المدفوعات والقيود المالية (`features/payment`):
- [ ] كتابة ملفات Flyway: `V7__create_payments.sql` و `V8__create_refunds.sql`.
- [ ] فرض قيد الـ `Idempotency-Key UNIQUE` على جدول المدفوعات.
- [ ] تطبيق الـ Pessimistic Lock (`SELECT FOR UPDATE`) على عقود الاشتراكات أثناء السداد.
- [ ] تفعيل الاشتراك تلقائياً وتحويله لـ `ACTIVE` فور اكتمال إجمالي السداد.
- [ ] إطلاق حدث `PaymentCompletedEvent` عبر Spring Application Event Bus.
- [ ] كتابة خدمة الاسترداد المالي العكسي `RefundService` مع اشتراط موافقة المدير وتوثيق السبب.
- [ ] **نقطة التحقق 2:** اختبار عمليات السداد المتزامنة، ومنع تكرار التحصيل، والتحقق من سلامة الأقساط الجزئية.

- [ ] خصم الحصص لباقات الـ `SESSION_PACK` والتحذير من تكرار الدخول في نفس اليوم مع إمكانية التمرير (Override).
- [ ] ربط Endpoint تسجيل الحضور: `POST /api/v1/checkins`.

### محرك تقييم المخاطر الذكي (`features/risk` & ShedLock):

- [ ] إعداد قفل المهام الموزع عبر PostgreSQL و ShedLock لمنع تكرار الوظائف المجدولة.
- [ ] كتابة الوظيفة الليلية لتحديث الاشتراكات المنتهية ونقلها لـ `GRACE` أو `EXPIRED`.
- [ ] برمجة خوارزمية احتساب درجة المخاطر الحسابية (0 إلى 100) وتوليد الأسباب ومسودة الرسالة بالعربية.

- [ ] تطبيق قيود منع الإزعاج (حد أقصى رسالة كل 3 أيام وساعات الإرسال 9ص-9م).
- [ ] برمجة محرك نسبة العائد (Renewal Attribution) لربط التجديدات بالرسائل المرسلة.
- [ ] كتابة استعلامات لوحة تحكم صاحب الجيم في `DashboardService` واحتساب إيرادات الشهر ونسب التجديد.
- [ ] ربط Endpoints طابور الواتساب ولوحة التحكم: `/api/v1/notifications/queue` و `/api/v1/dashboard/summary`.

### سجل الرقابة والعمليات الحساسة (`features/audit`):
- [ ] كتابة ملف Flyway: `V13__create_audit_logs.sql`.
- [ ] بناء كيان ومسجل التدقيق غير القابل للتعديل لتوثيق الخصومات والتجميد والاسترداد وتجاوزات الحضور.
- [ ] **نقطة التحقق 3:** تجربة دورة يومية كاملة: تسجيل حضور -> تسجيل دفع -> احتساب مخاطر ليلية -> ظهور رسالة واتساب في طابور الصباح.

## 6. قائمة متابعة المرحلة 4: الإحكام الأمني، التجهيز والإطلاق الميداني (Weeks 10 to 12)

### الإحكام السحابي والتشغيلي:
- [ ] استئجار وتجهيز خادم VPS (Ubuntu 24.04 LTS) مع Docker و Docker Compose.
- [ ] إعداد Nginx Reverse Proxy وتركيب شهادة SSL مشفرة تلقائياً عبر Let's Encrypt.
- [ ] ضبط الجدار الناري UFW وإغلاق جميع المنافذ عدا 80 و 443 و SSH.
- [ ] كتابة سكربت النسخ الاحتياطي اليومي المشفر لـ PostgreSQL وإرساله لمخزن سحابي خارجي واختبار استرجاعه بنجاح.
- [ ] تفعيل مراقبة الأخطاء في الوقت الفعلي عبر **Sentry** وتأمين مسارات Spring Boot Actuator.

### التجهيز الميداني والتشغيل التجريبي:
- [ ] استيراد بيانات أعضاء واشتراكات الجيم التجريبي من ملف الإكسيل الفعلي للجيم.
- [ ] عقد جلسة تدريبية لموظفي الاستقبال وشرح شاشات الحضور واستخدام روابط `wa.me`.
- [ ] طباعة ورقة إرشادية مختصرة بجوار كمبيوتر الاستقبال.
- [ ] **نقطة التحقق 4 (تشغيل الـ Pilot لمدة 14 يوماً):**
  - [ ] تشغيل الجيم التجريبي بنسبة حضور مسجلة لا تقل عن 70% عبر السيستم.
  - [ ] عدم اللجوء للدفاتر الورقية خلال فترة التجربة.
  - [ ] قياس رضا صاحب الجيم وإثبات الإيرادات المستردة عبر لوحة التحكم.
