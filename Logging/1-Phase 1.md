# 1️⃣ يعني إيه Logging؟

**Logging** هو عملية تسجيل الأحداث (Events) اللي بتحصل جوه البرنامج أثناء تشغيله.
Logging means recording events, messages, or data generated by a program while it runs, usually saved to a file or console for later review.

It helps developers track what happened, debug issues, and monitor system behavior over time.

بدل ما البرنامج يشتغل في صمت، بيكتبلك كل اللي بيحصل.

مثلاً:

- User عمل Login.
    
- API اتطلبت.
    
- Database رجعت Error.
    
- Service بدأت Processing.
    
- Payment نجح.
    
- Exception حصل.
    

كل ده بيتسجل في Logs.

تخيل إن البرنامج زي طيارة.

الـ **Black Box** بتاع الطيارة هو الـ Logging.

لو حصل Crash هترجع تشوف حصل إيه.

---

# ليه أصلاً نستخدم Logging؟

عشان نعرف:

- البرنامج عمل إيه.
    
- وصل لفين.
    
- حصل Error فين.
    
- الأداء كان عامل إزاي.
    
- مين استخدم السيستم.
    
- ليه الـ Bug حصل.
    

---

# مثال

بدون Logging

```java
public void register(User user) {
    repository.save(user);
}
```

لو حصل Error...

مش هتعرف:

- وصل هنا؟
    
- حفظ؟
    
- وقف فين؟
    

---

مع Logging

```java
public void register(User user) {

    log.info("Registering user {}", user.getEmail());

    repository.save(user);

    log.info("User saved successfully.");
}
```

هتلاقي في الـ Console

```
Registering user ali@gmail.com
User saved successfully.
```

عرفت البرنامج عمل إيه خطوة بخطوة.

# 3️⃣ Log Levels

دي أهم نقطة.

كل Log ليه درجة أهمية.

من الأقل للأعلى:

```
TRACE

↓

DEBUG

↓

INFO

↓

WARN

↓

ERROR
```

كل Level ليه استخدام مختلف.

---

# TRACE

أقل مستوى.

بيستخدم في تفاصيل دقيقة جدًا.

Developer بيشوف كل خطوة.

مثلاً

```
Entering calculatePrice()
```

```
Loop iteration = 15
```

```
Generated SQL
```

---

مثال

```java
log.trace("Entering calculatePrice()");
```

وده غالبًا بيتقفل في الـ Production لأنه هيطلع كمية Logs ضخمة.

---

## إمتى أستخدم TRACE؟

لو بتعمل Debug لخوارزمية معقدة أو عايز تتبع كل خطوة.

---

# DEBUG

أكثر استخدامًا أثناء التطوير.

بيعرض معلومات تساعدك تفهم البرنامج بيعمل إيه.

مثلاً

```
Fetching user with id 5
```

```
JWT Token Parsed
```

```
Calling Payment API
```

---

مثال

```java
log.debug("Fetching user {}", id);
```

---

لو حصل Bug

هتشغل DEBUG.

بعد ما تحل المشكلة

تقفله.

---

## إمتى أستخدم DEBUG؟

- أثناء التطوير.
    
- عند تتبع Flow.
    
- لفهم تنفيذ الكود.
    

---

مثال

# ترتيبهم في جدول

|Level|يستخدم في|مثال|
|---|---|---|
|TRACE|تفاصيل دقيقة جدًا أثناء التتبع|دخول/خروج الدوال، كل خطوة في خوارزمية|
|DEBUG|معلومات للمطور أثناء التطوير|Fetch User، Call API، Parse JWT|
|INFO|أحداث طبيعية مهمة|User Registered، Server Started|
|WARN|مشكلة غير حرجة|Cache Miss، Disk Space Low|
|ERROR|فشل أو Exception|DB Down، Payment Failed|

---

# مثال عملي داخل Service

```java
public void placeOrder(Order order) {

    log.info("Starting order creation for user {}", order.getUserId());

    log.debug("Order contains {} items", order.getItems().size());

    if (order.getItems().isEmpty()) {
        log.warn("User {} tried to create an empty order", order.getUserId());
        return;
    }

    try {
        repository.save(order);
        log.info("Order saved successfully");
    } catch (Exception e) {
        log.error("Failed to save order", e);
    }
}
```

**ماذا سيظهر؟**

- عند بداية العملية: `INFO` يوضح بدء إنشاء الطلب.
    
- أثناء التطوير: `DEBUG` يوضح عدد العناصر.
    
- إذا كان الطلب فارغًا: `WARN` لأن البرنامج لم ينهار لكن هناك استخدام غير متوقع.
    
- إذا فشل الحفظ: `ERROR` مع الـ Stack Trace لمعرفة سبب الفشل.
    

---

# سؤال انترفيو مهم جدًا

**ليه منستخدمش `ERROR` لكل الرسائل؟**

لأن الـ Log Levels معمولة لتصنيف أهمية الأحداث. لو كل حاجة اتسجلت كـ `ERROR`، هتضيع الأخطاء الحقيقية وسط رسائل عادية، وهتبقى أدوات المراقبة (Monitoring) بتتعامل مع كل رسالة كأنها مشكلة خطيرة.

---

# أفضل الممارسات

- استخدم `TRACE` للتفاصيل الدقيقة جدًا عند الحاجة.
    
- استخدم `DEBUG` لمعلومات تساعد المطور أثناء التطوير.
    
- استخدم `INFO` للأحداث الطبيعية المهمة في النظام.
    
- استخدم `WARN` للمشكلات غير الحرجة التي لا توقف التنفيذ.
    
- استخدم `ERROR` فقط عند حدوث فشل حقيقي أو Exception.
    
- لا تسجل معلومات حساسة مثل كلمات المرور أو مفاتيح الـ API أو أرقام البطاقات البنكية.
    

---

## الخلاصة (الزتونة)

```
TRACE
↓
تفاصيل دقيقة جدًا (نادراً في Production)

DEBUG
↓
معلومات للمطور أثناء Debugging

INFO ⭐
↓
الأحداث الطبيعية المهمة (الأكثر استخدامًا)

WARN
↓
مشكلة غير حرجة، البرنامج ما زال يعمل

ERROR
↓
فشل أو Exception يحتاج إلى متابعة
```

دي هي الأساسيات اللي لازم تكون فاهمها قبل ما تدخل على **SLF4J**، و`@Slf4j`، و**Logback**، والـ **Configuration**، والـ **Pattern Layout**، والـ **File Logging**، و**Log Rotation**، لأن كل الحاجات دي مبنية على المفاهيم اللي فوق.
