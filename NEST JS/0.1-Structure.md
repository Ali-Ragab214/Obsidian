سؤال ممتاز 👌 لأن **Structure NestJS الصح** هو اللي بيفرق بين مشروع CRUD عادي ومشروع Graduation محترم.

خلينا نبني Structure Production-ready زي الشركات 👇

---

# 🏗️ أولاً: الفكرة الأساسية في Nest Architecture

Nest قائم على 3 أفكار رئيسية:

- Modular Architecture
    
- Separation of Concerns
    
- Reusability (Common Layer)
    

يعني بنقسم المشروع إلى:

- Modules (features)
    
- Common (shared)
    
- Config / infrastructure
    

---

# 📁 الشكل النهائي للمشروع (Production Structure)

ده الشكل اللي أنصحك تستخدمه في مشروع التخرج:

```
src/
│
├── main.ts
├── app.module.ts
│
├── modules/
├── common/
├── database/
├── config/
└── types/
```

دلوقتي نشرح كل فولدر بالتفصيل 👇

---

# 🚀 1) main.ts

ده Entry Point بتاع التطبيق.

وظيفته:

- تشغيل السيرفر
    
- تفعيل Global pipes / filters / interceptors
    
- تفعيل Swagger
    

مثلاً هنا بتعمل:

- Global ValidationPipe
    
- CORS
    
- Helmet
    
- Swagger
    

---

# 🧩 2) app.module.ts

ده Root Module  
بيجمع كل Modules المشروع.

مثلاً:

```ts
imports: [
  ConfigModule,
  DatabaseModule,
  AuthModule,
  UsersModule,
  JobsModule,
]
```

---

# 📦 3) modules/ (أهم فولدر)

ده قلب المشروع ❤️  
كل Feature يبقى Module مستقل.

مثلاً:

```
modules/
   auth/
   users/
   jobs/
   applications/
   uploads/
```

كل Module = Feature كاملة.

---

## شكل أي Module من جوا

نأخذ مثال users module:

```
users/
   users.module.ts
   users.controller.ts
   users.service.ts
   users.repository.ts
   entities/
   dto/
```

نشرح كل جزء 👇

---

### 🎮 users.controller.ts

Layer بتاع الـ HTTP

مسؤول عن:

- Routes
    
- Request/Response
    
- Guards
    

مفيش business logic هنا ❌

---

### 🧠 users.service.ts

Business Logic Layer

هنا:

- Validation logic
    
- Rules
    
- Calling repository
    

ده أهم ملف في الموديول.

---

### 🗄️ users.repository.ts

Data Access Layer

هنا التعامل مع:

- Prisma / TypeORM
    
- Queries
    
- DB logic فقط
    

فصل الـ repository ده يخلي المشروع Professional جداً.

---

### 🧾 dto/

Data Transfer Objects

```
dto/
   create-user.dto.ts
   update-user.dto.ts
   login.dto.ts
```

وظيفته:

- Validation
    
- Shape of request
    

---

### 🧱 entities/

DB Models

```
entities/
   user.entity.ts
```

تمثل جداول الداتابيز.

---

# 🧰 4) common/ (أهم فولدر احترافي)

ده Shared Layer  
أي حاجة reusable تتحط هنا.

```
common/
   decorators/
   guards/
   filters/
   interceptors/
   pipes/
   exceptions/
   utils/
```

نشرح كل واحد 👇

---

## 🧩 decorators/

Custom decorators

زي:

- @CurrentUser()
    
- @Roles()
    

---

## 🛡️ guards/

Authorization logic

زي:

- JwtAuthGuard
    
- RolesGuard
    

الفرق المهم:

- Guard بيقرر يدخل الريكوست ولا لا.
    

---

## ⚠️ filters/

Global Error Handling

هنا تحط:

- HttpExceptionFilter
    
- Custom Exceptions
    

ده زي GlobalExceptionHandler في Spring.

---

## 🔄 interceptors/

تشغيل كود قبل وبعد الريكوست.

أمثلة:

- Logging interceptor
    
- Transform response
    
- Cache interceptor
    

---

## 🧪 pipes/

Validation & transformation

زي:

- ValidationPipe
    
- ParseIntPipe
    
- Custom pipes
    

---

## ❌ exceptions/

Custom exceptions

زي:

- NotFoundException
    
- UnauthorizedException
    
- ConflictException
    

---

## 🧰 utils/

Helper functions

زي:

- hashPassword
    
- generateToken
    
- pagination helper
    

---

# 🗄️ 5) database/

كل ما يخص الداتابيز.

```
database/
   prisma/
   migrations/
   seed/
   database.module.ts
```

لو Prisma:

- prisma.service.ts
    
- schema.prisma
    

---

# ⚙️ 6) config/

Environment configuration.

```
config/
   app.config.ts
   jwt.config.ts
   database.config.ts
```

يقرأ من `.env`

ده Production practice مهم جداً.

---

# 🧾 7) types/

Custom TypeScript types & enums.

```
types/
   roles.enum.ts
   pagination.interface.ts
```

---

# 🧠 الخلاصة الذكية

المشروع بيتقسم 3 Layers:

|Layer|المكان|
|---|---|
|Feature modules|modules/|
|Shared reusable code|common/|
|Infrastructure|config + database|

ده Structure Production فعلاً 👌

---
