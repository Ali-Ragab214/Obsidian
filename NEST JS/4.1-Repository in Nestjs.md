

## السؤال بتاعك كان:

لما أكتب

```bash
nest g resource users
```

ليه مش بيعمل **UserRepository** ؟

---

## 🧠 الأول لازم نفهم حاجة مهمة جداً

NestJS = **Framework بس**  
مش ORM ومش Database framework.

يعني Nest مسؤول عن:

- Controller
    
- Service
    
- Modules
    
- DI (حقن الكلاسات ببعض)
    

لكن **مش مسؤول عن قاعدة البيانات**.

قاعدة البيانات ليها أدوات تانية اسمها ORM زي:

- TypeORM
    
- Prisma
    
- Sequelize
    
- Mongoose
    

علشان كده Nest مش بيعمل Repository.

---

## تخيلها كده 🎯

انت بتبني مطعم 🍔

NestJS = المطعم نفسه  
ORM = المطبخ 👨‍🍳

هل المطعم يقدر يعمل أكل لو مفيش مطبخ؟ ❌  
لازم انت تختار المطبخ الأول.

---

## طيب ايه اللي بيحصل لما تعمل resource ؟

لما تكتب:

```bash
nest g resource users
```

Nest بيقولك:

> انا هعملك **طبقات التطبيق** بس

فيطلعلك:

```
users/
 ├─ users.controller.ts
 ├─ users.service.ts
 ├─ users.module.ts
 ├─ dto/
 └─ entities/user.entity.ts
```

خد بالك 👇  
عملك **Entity class بس** مش Repository.

ليه؟ لأنه لسه **مش عارف انت هتستخدم أي ORM**.

---

## طيب امتى يظهر Repository ؟

أول ما تختار ORM.

خلينا نمشي خطوة خطوة 👇

### 1️⃣ نثبت TypeORM

```bash
npm install @nestjs/typeorm typeorm mysql2
```

دلوقتي بس Nest فهم:

> اوكي 👌 احنا هنستخدم TypeORM

---

### 2️⃣ نربط الـ Entity بالداتا بيز

في `users.module.ts` نضيف:

```ts
imports: [TypeOrmModule.forFeature([User])]
```

الجملة دي معناها:

> يا Nest اعمل Repository للـ User Entity

💥 هنا بس Nest ينشئ Repository تلقائي.

انت مش بتشوفه كملف، لكنه **اتعمل جوه الـ DI container**.

---

### 3️⃣ نستخدم Repository في Service

```ts
constructor(
  @InjectRepository(User)
  private userRepo: Repository<User>,
) {}
```

أول ما كتبت السطر ده حصل ايه؟

Nest قال:

> حاضر 😎 ده Repository جاهز اهو

يعني Nest عمل Repository **وقت التشغيل** مش كملف.

---

## 💡 ليه مفيش ملف Repository ؟

في Spring مثلاً بتعمل Interface Repository.

لكن TypeORM شغال بطريقة مختلفة:

هو بيعمل Generic Repository جاهز اسمه:

```
Repository<User>
```

فيه كل الدوال جاهزة:

- save()
    
- find()
    
- findOne()
    
- delete()
    

يعني مش محتاج تكتب Repository بنفسك أصلاً.

---

## 🧾 الخلاصة السهلة جداً تحفظها

قبل ORM:

```
Nest = يعمل Service و Controller بس
```

بعد ORM:

```
ORM = يعمل Repository تلقائي
Nest = يحقنه في Service
```

يعني:

> Repository تابع للـ ORM مش Nest

---

لو حابب نرسم Flow صغير يثبت المعلومة في دماغك أو نعمل مثال كامل CRUD بالـ Repository خطوة خطوة نقفل الموضوع نهائي 💪
