# `nest g resource users` بيعمل اي أصلًا ؟

الكوماند ده بيولد بسرعة:

```txt
users/
├── dto
├── entities
├── users.controller.ts
├── users.service.ts
├── users.module.ts
```

وده ممتاز جدًا في:

- التعلم
    
- CRUD سريع
    
- Prototype
    
- مشاريع صغيرة
    

---

# المشكلة في مشروع كبير

هو بيولد Structure أقرب لـ:

```txt
users/
│
├── dto/
├── entities/
├── users.controller.ts
├── users.service.ts
└── users.module.ts
```

لكن أنت لو شغال Clean Architecture فغالبًا محتاج:

```txt
users/
│
├── domain/
├── application/
├── infrastructure/
├── presentation/
└── users.module.ts
```

فالكوماند مش فاهم إنك عايز:

- Repository interfaces
    
- Use cases
    
- Infrastructure layer
    
- Domain layer
    
- Custom repositories
    

---

# في الشركات بيعملوا اي غالبًا ؟

في مشاريع كبيرة غالبًا:

يستخدموا أوامر Nest لبعض الحاجات فقط:

```bash
nest g module users
nest g controller users
nest g service users
```

وبعدين ينظموا الـ Structure بإيدهم.

---

# مثال شائع جدًا

بدل:

```bash
nest g resource users
```

يعملوا:

```bash
nest g module users

nest g controller users/presentation

nest g service users/application
```

وبعدين بإيدهم:

```txt
users/
│
├── domain/
│   ├── entities/
│   ├── repositories/
│   └── enums/
│
├── application/
│   ├── services/
│   └── dto/
│
├── infrastructure/
│   └── repositories/
│
├── presentation/
│   └── users.controller.ts
│
└── users.module.ts
```

# هل تعمل كل Layers بإيدك ؟

في البداية:

✅ آه

لسبب مهم جدًا:

أنت لسه بتتعلم Architecture.

لما تعملها بإيدك:

- هتفهم كل Layer ليه موجودة
    
- هتفهم Dependency Flow
    
- هتفهم Repository Pattern
    
- هتفهم Separation of Concerns
    

---

بعد ما تتمكن وتعمل كذا مشروع:

ممكن تعمل لنفسك:

- Custom Schematics
    
- Boilerplates
    
- Starter Templates
    

بحيث تولد الـ Structure تلقائي.

ودي أصلًا حاجة شركات كتير بتعملها.

---

# لو هنطبق ده على مشروع ITI بتاعك

أنا لو مكانك:

❌ مش هستخدم:

```bash
nest g resource
```

هستخدم:

```bash
nest g module
nest g controller
nest g service
```

وأرتب Layers بإيدي.

لأنك أصلًا بتتعلم:

- Clean Architecture
    
- Repository Pattern
    
- Scalability
    
- Production Structure
    

مش مجرد CRUD.

وأنت بدأت تدخل المنطقة اللي فعلًا تفرق في مشروع تخرج محترم.
