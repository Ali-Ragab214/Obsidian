# 1) Framework vs Library

## Library

الـ Library عبارة عن أدوات أنت بتستخدمها وقت ما تحب.

بمعنى:

> **أنت اللي بتنادي على المكتبة.**

مثال:

```js
import axios from "axios";

axios.get("/users");
```

هنا أنت اللي استدعيت Axios بنفسك.

---

## Framework

الـ Framework هو اللي بيدير التطبيق بالكامل، وأنت بتحط الكود في الأماكن اللي هو محددها.

يعني:

> **الـ Framework هو اللي بينادي على كودك.**

مثال:

```ts
@Controller()
export class UserController {

    @Get()
    findAll() {
        return "users";
    }

}
```

أنت مش بتستدعي `findAll()` بنفسك.

Nest هو اللي بيشوف إن فيه Request جاي على:

```http
GET /users
```

ويروح ينادي الميثود تلقائيًا.

وده اسمه:

# Inversion Of Control (IoC)
صح تمام، الفهم ده دقيق جداً وده بالظبط الفرق الأساسي (Inversion of Control):

**Library:**

- انت اللي بتـ call الكود بتاعها
- بتستخدمها "as a tool" وقت ما تحب، فيها flexibility كبيرة
- مثال: لو عندك utility library زي Lodash أو حتى JDBC، انت اللي بتكتب الـ main flow وبتستدعيها هي وقت ما محتاجها

**Framework:**

- هو اللي بيـ call الكود بتاعك (Hollywood Principle: "Don't call us, we'll call you")
- بيحدد لك "skeleton" أو "structure" للتطبيق، وانت بتـ plug in الكود بتاعك في الأماكن اللي هو محددها (hooks, annotations, lifecycle methods)
- مثال على Spring Boot بالظبط: انت مش اللي بتعمل `new UserController()` وتستدعيها — Spring هو اللي بيـ scan الـ `@RestController` وبيعمل instantiate وبيـ call الـ methods بتاعتك وقت ما يجيله request، وانت بس حطيت الكود جوه الـ annotations والـ structure اللي هو محددها.

نفس الكلام مع:

- `@Entity` في JPA — انت مش اللي بتـ call الـ persistence logic، الـ framework هو اللي بيتعامل معاها
- `@CacheEvict` بتاعتك في Skill_Hub — انت كتبت الـ logic، بس Spring هو اللي بيقرر امتى ينادي عليها (before/after method execution)

ده كمان بيوضح ليه الـ framework أصعب في الـ debugging شوية — لأن flow الكود مش واضح من جوه الكود بتاعك نفسه، لازم تفهم إزاي الـ framework بيـ call الأشياء عشان تعرف تتبع المشكلة (زي الـ 500 error اللي كان بسبب الـ `@Formula` وانت مكنتش شايف الـ call chain مباشرة).

# 21) ما هو Query ؟

لو عندك:

```http
GET /users?page=1&size=10
```

فإن:

```ts
@Query() query
```

يساوي:

```ts
{
   page: "1",
   size: "10"
}
```

---

مثال:

```ts
@Get()
findAll(@Query() query) {
    return query;
}
```

النتيجة:

```json
{
  "page":"1",
  "size":"10"
}
```

---

يمكن أيضًا:

```ts
@Get()
findAll(
    @Query("page") page:number
){
    return page;
}
```

# 23) DTO

DTO =

```text
Data Transfer Object
```

الغرض منه:

- تحديد شكل البيانات.
    
- التحقق من صحة البيانات.
    
- منع استقبال بيانات غير مطلوبة.
    

---

مثال:

```ts
export class CreateUserDto {

    name:string;

    email:string;

    password:string;

}
```

---

بدل:

```ts
@Post()
create(@Body() body:any)
```

نستخدم:

```ts
@Post()
create(
    @Body() dto:CreateUserDto
)
```

---

# 24) لماذا DTO Class وليس Interface ؟

لأن:

```text
Interfaces disappear at runtime
```

بعد الـ Compilation يتم حذف الـ Interface.

---

أما الـ Class:

يبقى موجودًا داخل Runtime.

والـ Pipes تعتمد على ذلك.

---

مثال:

```ts
create(dto:CreateUserDto)
```

Nest يستطيع معرفة:

```text
CreateUserDto
```

في Runtime.

أما:

```ts
create(dto:IUser)
```

لن يستطيع.

# 26) PartialType

```ts
export class UpdateUserDto
extends PartialType(CreateUserDto) {}
```

يجعل جميع الحقول:

```text
Optional
```

لو:

```ts
class CreateUserDto {
   name:string;
   email:string;
}
```

تصبح:

```ts
class UpdateUserDto {
   name?:string;
   email?:string;
}
```

---

# 27) PickType

```ts
export class UpdateUserDto
extends PickType(
    CreateUserDto,
    ['name','email']
)
{}
```

ينسخ فقط:

```text
name
email
```

---

يوجد أيضًا:

## OmitType

يحذف حقول معينة.

```ts
extends OmitType(
    CreateUserDto,
    ['password']
)
```

# 28) HttpException

تستخدم لإرجاع أخطاء HTTP مخصصة.

---

مثال:

```ts
throw new HttpException(
    "User not found",
    HttpStatus.NOT_FOUND
);
```

الرد:

```json
{
    "statusCode":404,
    "message":"User not found"
}
```

---

مثال آخر:

```ts
if(age < 18){
    throw new HttpException(
        "Age must be greater than 18",
        HttpStatus.BAD_REQUEST
    );
}
```

---

لكن الأفضل غالبًا استخدام Exceptions الجاهزة:

```ts
throw new NotFoundException();

throw new BadRequestException();

throw new UnauthorizedException();

throw new ForbiddenException();

throw new ConflictException();
```

---

مثال:

```ts
if(!user){
    throw new NotFoundException(
        "User not found"
    );
}
```

# 29) مقارنة سريعة مع Spring Boot

|NestJS|Spring Boot|
|---|---|
|Controller|RestController|
|Service|Service|
|Module|Package + Configuration|
|Provider|Bean|
|DTO|DTO|
|Pipe|Validation|
|Exception|Exception Handler|
|Dependency Injection|Dependency Injection|
|main.ts|main()|

	لو كملت في Nest هتلاحظ إنه أقرب Framework في عالم JavaScript إلى Spring Boot من ناحية الـ Architecture والـ Dependency Injection والـ Decoratorا
