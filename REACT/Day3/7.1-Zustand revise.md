# إنشاء Store

```js
// store/cartStore.js

import { create } from "zustand";

export const useCartStore = create((set) => ({
  cart: [],

  addToCart: (product) =>
    set((state) => ({
      cart: [...state.cart, product],
    })),

  removeFromCart: (productId) =>
    set((state) => ({
      cart: state.cart.filter(
        (product) => product.id !== productId
      ),
    })),

  clearCart: () =>
    set({ cart: [], }),
}));
```

# مثال كامل

## ProductCard.jsx

```jsx
import { useCartStore } from "../store/cartStore";

export default function ProductCard() {

  const addToCart = useCartStore(
    (state) => state.addToCart
  );

  const product = {
    id: 1,
    name: "Laptop",
  };

  return (
    <button
      onClick={() => addToCart(product)}
    >
      Add To Cart
    </button>
  );
}
```

## Cart.jsx

import { useCartStore } from "../store/cartStore";

export default function Cart() {

      {cart.map((item) => (

          {item.name}

# الفرق بين Redux و Zustand

|Zustand|Redux Toolkit|
|---|---|
|بسيط جدًا|أكبر|
|كود قليل|كود أكثر|
|سهل للمبتدئين|يحتاج فهم أعمق|
|ممتاز لمعظم المشاريع|ممتاز للمشاريع الضخمة جدًا|
|Store + Actions|Store + Reducers + Actions|

# معلومة مهمة جدًا للمقابلات

State نوعين:

### Local State

داخل Component واحدة

```jsx
const [count,setCount] = useState(0)
```

---

### Global State

محتاجة أكثر من Component

```txt
User
Cart
Theme
Language
Notifications
```

هنا نستخدم:

- Context API
    
- Zustand
    
- Redux
    

وليس `useState`.

وده بالضبط السبب الحقيقي لوجود Zustand. هو أداة لإدارة **Global State** بحيث أي Component في التطبيق يقدر يقرأ ويعدل البيانات بدون Prop Drilling وبدون تعقيد Redux.
