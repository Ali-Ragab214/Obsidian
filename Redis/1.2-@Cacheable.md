تمام. بما إنك بالفعل فاهم Redis و Cache بشكل عام، فخلينا نركز على **@Cacheable عمليًا** ونشوف سيناريوهات حقيقية هتقابلك في مشاريع Spring Boot.

---

# الفكرة الأساسية

تخيل عندك Method بتجيب بيانات من DB:

```java
public Course getCourseById(Long id) {
    return courseRepository.findById(id)
            .orElseThrow();
}
```

كل مرة تتنادى:

```text
Client
 ↓
Service
 ↓
Database
```

حتى لو نفس الـ ID.

مع `@Cacheable`:

```java
@Cacheable("courses")
public Course getCourseById(Long id) {
    return courseRepository.findById(id)
            .orElseThrow();
}
```

أول مرة:

```text
Cache Miss
↓
DB
↓
Store in Cache
```

ثاني مرة:

```text
Cache Hit
↓
Redis
```

من غير DB.

---

# مثال 1: Cache باستخدام Parameter

```java
@Service
@RequiredArgsConstructor
public class CourseService {

    private final CourseRepository repository;

    @Cacheable("courses")
    public Course getCourseById(Long id) {

        System.out.println("Fetching from DB...");

        return repository.findById(id)
                .orElseThrow();
    }
}
```

---

تشغيل:

```java
courseService.getCourseById(1L);
courseService.getCourseById(1L);
courseService.getCourseById(1L);
```

الـ Console:

```text
Fetching from DB...
```

هتظهر مرة واحدة فقط.

---

## Spring بيخزن إيه؟

المفتاح تلقائيًا:

```text
courses::1
```

يعني:

```text
Cache Name + Parameter
```

# مثال 3: تخصيص المفتاح Key

بدل ما Spring يركب Key تلقائي.

```java
@Cacheable(
    value = "courses",
    key = "#id"
)
public Course getCourseById(Long id) {
    return repository.findById(id).orElseThrow();
}
```

---

لو عندك Object:

```java
public record CourseRequest(
        Long id,
        String language
) {}
```

---

ممكن:

```java
@Cacheable(
    value = "courses",
    key = "#request.id"
)
public Course getCourse(CourseRequest request) {
    ...
}
```

---

هنا المفتاح:

```text
courses::5
```

بدل Object كامل.

# مثال 5: عدم تخزين Null

بدون شرط:

```java
@Cacheable("users")
public User getUser(Long id) {
    return repository.findById(id)
            .orElse(null);
}
```

---

لو الـ User مش موجود:

```text
null
```

ممكن يتخزن في Cache.

---

الأفضل:

```java
@Cacheable(
    value = "users",
    unless = "#result == null"
)
public User getUser(Long id) {

    return repository.findById(id)
            .orElse(null);
}
```

---

معنى:

```java
unless = "#result == null"
```

يعني:

```text
لو النتيجة Null
↓
متخزنهاش
```

# مثال 7: شرط قبل التخزين condition

```java
@Cacheable(
    value = "courses",
    condition = "#id > 100"
)
public Course getCourse(Long id) {

    return repository.findById(id)
            .orElseThrow();
}
```

---

هنا:

```java
getCourse(50L);
```

❌ لن يعمل Cache.

---

لكن:

```java
getCourse(150L);
```

✅ سيتخزن.

# مثال 8: SkillHub Project

نفترض:

```java
@GetMapping("/{id}")
public CourseResponse getCourse(Long id)
```

الكورسات بتتقري آلاف المرات.

---

Service:

```java
@Cacheable(
    value = "course-details",
    key = "#id"
)
public CourseResponse getCourse(Long id) {

    Course course = repository.findById(id)
            .orElseThrow();

    return mapper.toResponse(course);
}
```

---

الفلو:

```text
Request
 ↓
Cache Check
 ↓
Hit؟
 ↓
Yes → Redis
 ↓
No
 ↓
DB
 ↓
Store in Redis
 ↓
Return
```

# خطأ مهم جدًا

بص للكود ده:

```java
@Service
public class CourseService {

    @Cacheable("courses")
    public Course getCourse(Long id) {
        ...
    }

    public void test() {
        getCourse(1L);
    }
}
```

---

هنا الـ Cache **لن يعمل**.

ليه؟

لأن Spring بيستخدم Proxy.

ولما تنادي Method من نفس الكلاس:

```java
this.getCourse(...)
```

الـ Proxy بيتخطى.

---

لازم النداء ييجي من Bean تانية:

```text
Controller
 ↓
Service
 ↓
Cache Proxy
 ↓
Method
```

# أهم Properties في @Cacheable

|Property|وظيفتها|
|---|---|
|value|اسم الـ Cache|
|cacheNames|نفس value|
|key|تخصيص المفتاح|
|condition|شرط قبل الـ Cache|
|unless|شرط بعد النتيجة|
|sync|يمنع Cache Stampede|

احفظ القاعدة دي:

```text
@Cacheable
    ↓
للـ Read

@CachePut
    ↓
لتحديث الـ Cache

@CacheEvict
    ↓
لمسح الـ Cache
```

ودي التلاتة اللي هتستخدمهم في 95% من شغلك مع Spring Cache وRedis.
