# Redis Caching with Spring Boot - Complete Notes

## What is Redis?

Redis is an **in-memory key-value data store**. It stores data in RAM instead of disk, which makes it extremely fast.

Redis is commonly used for:

- Caching
    
- Session storage
    
- Rate limiting
    
- Pub/Sub messaging
    
- Distributed locking
    

In our projects, we mainly use Redis as a **distributed cache**.

---

# Why do we use Redis?

Without caching:

```
Client
   ↓
Spring Boot Application
   ↓
Database
   ↓
Client
```

Every request hits the database.

Example:

```
1000 users request the same course
↓
1000 database queries
```

This increases database load and slows down the application.

---

With Redis caching:

### First Request

```
Client
   ↓
Application
   ↓
Redis Cache ? → Cache Miss
   ↓
Database
   ↓
Save result in Redis
   ↓
Return response
```

### Second Request

```
Client
   ↓
Application
   ↓
Redis Cache ? → Cache Hit
   ↓
Return response
```

The database is not accessed.

---

# Where is Redis Cache Stored?

Redis cache is NOT stored on the user's device.

Redis runs as a separate server.

Example:

```
Users
   ↓
Spring Boot Application
   ↓
Redis Server
   ↓
Database
```

All application instances can share the same Redis cache.

---

# Redis vs Local Cache

## Local Cache

Stored inside the application's RAM.

Example:

- Caffeine
    
- ConcurrentHashMap
    

```
Spring Boot App
    ↓
Application RAM
```

If the application stops, the cache is lost.

---

## Redis Cache

Stored in a separate Redis server.

```
Spring App 1
      \
       Redis
      /
Spring App 2
```

Benefits:

- Shared across multiple instances
    
- Faster than database access
    
- Better for production systems
    

---

# How Redis Stores Data

Redis stores data as:

```
Key → Value
```

Example:

```
courses::1
↓
{
    "id": 1,
    "title": "Java Masterclass",
    "price": 100
}
```

Redis internally stores data as bytes.

# Spring Boot Dependencies

Add these dependencies:

```xml
<!-- Spring Cache Abstraction -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-cache</artifactId>
</dependency>

<!-- Redis Integration -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
```

## Why both?

### spring-boot-starter-cache

Provides the Spring Cache abstraction and annotations:

- @Cacheable
    
- @CacheEvict
    
- @CachePut
    

---

### spring-boot-starter-data-redis

Connects Spring Boot to Redis.

Redis becomes the actual cache implementation.

# Running Redis

The easiest way is Docker.

```bash
docker run -d --name redis -p 6379:6379 redis:latest
```

Explanation:

- `-d` → run in background
    
- `--name redis` → container name
    
- `-p 6379:6379` → expose Redis port
    

Redis runs on:

```
localhost:6379
```

# Enable Caching

In the main class:

```java
@SpringBootApplication
@EnableCaching
public class SkillHubApplication {

    public static void main(String[] args) {
        SpringApplication.run(SkillHubApplication.class, args);
    }
}
```

## What does @EnableCaching do?

It tells Spring:

> "Scan for caching annotations and enable cache management."

Without it, caching annotations do nothing.

---

# Redis Configuration

```java
@Configuration
public class RedisConfig {

    @Bean
    public RedisCacheManager cacheManager(
            RedisConnectionFactory connectionFactory) {

        RedisCacheConfiguration defaultConfig =
                RedisCacheConfiguration.defaultCacheConfig()

                .entryTtl(Duration.ofMinutes(10))

                .serializeKeysWith(
                        RedisSerializationContext.SerializationPair
                                .fromSerializer(
                                        new StringRedisSerializer()
                                )
                )

                .serializeValuesWith(
                        RedisSerializationContext.SerializationPair
                                .fromSerializer(
                                        new GenericJackson2JsonRedisSerializer()
                                )
                );

        return RedisCacheManager.builder(connectionFactory)
                .cacheDefaults(defaultConfig)
                .build();
    }
}
```

---

# Why Serialization?

Redis stores bytes.

Spring needs to know how to convert Java objects.

---

## Keys

Use:

```java
StringRedisSerializer
```

Example:

```
courses::1
```

instead of unreadable binary data.

---

## Values

Use:

```java
GenericJackson2JsonRedisSerializer
```

Example:

```json
{
  "id": 1,
  "title": "Java",
  "price": 100
}
```

JSON is human-readable and easy to debug.

---

# TTL (Time To Live)

TTL determines how long cached data remains in Redis.

Example:

```java
.entryTtl(Duration.ofMinutes(10))
```

Meaning:

```
Cache expires after 10 minutes.
```

After expiration:

```
Redis deletes the entry automatically.
```

# Cache Flow

## Cache Miss

```
Request
   ↓
Redis
   ↓
Not Found
   ↓
Database
   ↓
Redis
   ↓
Response
```

---

## Cache Hit

```
Request
   ↓
Redis
   ↓
Found
   ↓
Response
```

Database is skipped.

---

# @Cacheable

Used for READ operations.

```java
@Cacheable(value = "courses", key = "#id")
public CourseResponse getCourse(Long id) {

    return repository.findById(id)
            .orElseThrow();
}
```

How it works:

### First Call

```
getCourse(1)

Redis → Miss
Database → Query
Redis → Save
Response
```

---

### Second Call

```
getCourse(1)

Redis → Hit
Response
```

Database is not queried.

---

# @CacheEvict

Used to remove cache entries.

Usually used after updates or deletes.

```java
@CacheEvict(value = "courses", key = "#id")
public void deleteCourse(Long id) {

    repository.deleteById(id);
}
```

Flow:

```
Delete from DB
↓
Remove cache
```

---

# @CachePut

Used to update the cache.

```java
@CachePut(value = "courses", key = "#result.id")
public CourseResponse updateCourse(...) {

    return savedCourse;
}
```

Flow:

```
Update DB
↓
Update Redis
↓
Return Response
```

# Stale Data Problem

Example:

Initial value:

```
Course Price = 100
```

Redis stores:

```
100
```

Database stores:

```
100
```

---

Update database:

```
Course Price = 150
```

If Redis is not updated:

Redis:

```
100
```

Database:

```
150
```

This inconsistency is called:

> Stale Data

---

# Which is Better?

Most projects prefer:

```java
@CacheEvict
```

instead of:

```java
@CachePut
```

Reason:

```
Update DB
↓
Remove cache
↓
Next read rebuilds cache
```

Simpler and safer.

# Different TTL per Cache

Example:

```java
return RedisCacheManager.builder(connectionFactory)

    .withCacheConfiguration(
            "courses",
            defaultConfig.entryTtl(Duration.ofMinutes(10))
    )

    .withCacheConfiguration(
            "categories",
            defaultConfig.entryTtl(Duration.ofHours(1))
    )

    .withCacheConfiguration(
            "statistics",
            defaultConfig.entryTtl(Duration.ofMinutes(1))
    )

    .build();
```

# Important Notes

- Redis is not a replacement for the database.
    
- Redis improves performance by reducing database load.
    
- Redis stores data in RAM.
    
- Cache entries should have an expiration strategy.
    
- Be careful about stale data.
    
- Cache only frequently read and rarely changing data.
    

---

# Most Important Things to Remember

1. Redis is an in-memory key-value store.
    
2. Redis is commonly used for caching.
    
3. Add Cache and Redis dependencies.
    
4. Run Redis using Docker.
    
5. Configure Redis connection.
    
6. Enable caching using `@EnableCaching`.
    
7. Configure serialization and TTL.
    
8. Use `@Cacheable` for reads.
    
9. Use `@CacheEvict` after updates/deletes.
    
10. Understand the stale data problem.
    
11. Cache only suitable data.
    
12. Redis complements the database; it does not replace it.
