# 🧠 قبل ما نكتب Model أصلاً… Rails بيشتغل إزاي؟

Rails مبني على فكرة اسمها:

## MVC Architecture

يعني المشروع متقسم 3 أجزاء:

|جزء|وظيفته|
|---|---|
|Model|يتعامل مع الداتابيز|
|Controller|يستقبل الطلب ويقرر يعمل إيه|
|View|يظهر البيانات للمستخدم|

تخيل العميل فتح:

```
/posts
```

Rails يعمل:

1. يروح للـ **routes**
    
2. يحدد الـ **controller + action**
    
3. controller يكلم **model**
    
4. يرجع **response**


|---|---|---|

|DELETE|/posts/:id|destroy|

---

# 1️⃣ index → عرض كل البوستات

```ruby
def index
  @posts = Post.all
end
```

### بيحصل إيه؟

- المستخدم فتح `/posts`
    
- Rails ينفذ index
    
- Post.all = يجيب كل records من DB
    
- يحطهم في @posts عشان الـ View يستخدمهم
    

SQL اللي بيتنفذ:

```sql
SELECT * FROM posts;
```

---

# 2️⃣ show → عرض بوست واحد

```ruby
def show
  @post = Post.find(params[:id])
end
```

### params يعني إيه؟

لو الرابط:

```
/posts/5
```

Rails يحولها:

```ruby
params[:id] = 5
```

SQL:

```sql
SELECT * FROM posts WHERE id = 5;
```

---

# 3️⃣ new → فتح صفحة إنشاء بوست

```ruby
def new
  @post = Post.new
end
```

⚠️ لا يحفظ في DB  
بس بيعمل object فاضي عشان الفورم.

---

# 4️⃣ create → حفظ البوست

```ruby
def create
  @post = Post.new(post_params)

  if @post.save
    redirect_to @post
  else
    render :new
  end
end
```

### شرح خطوة خطوة:

#### Post.new(post_params)

ينشئ object بالقيم اللي جايه من الفورم.

#### save

يحفظ في الداتابيز.

لو نجح:

```
redirect_to @post
```

يروح لصفحة show.

لو فشل (validation):

```
render :new
```

يرجع للفورم مع الأخطاء.

---

# ⚠️ Strong Parameters (حماية مهمة)

في آخر الكنترولر:

```ruby
private

def post_params
  params.require(:post).permit(:title, :body)
end
```

ليه مهم؟  
عشان الهكر ميضيفش حقول مش مسموح بيها.

Rails يسمح فقط بالـ permitted fields.

---

# 5️⃣ edit → صفحة تعديل

```ruby
def edit
  @post = Post.find(params[:id])
end
```

يجيب البوست ويحطه في الفورم.

---

# 6️⃣ update → تحديث البيانات

```ruby
def update
  @post = Post.find(params[:id])

  if @post.update(post_params)
    redirect_to @post
  else
    render :edit
  end
end
```

SQL:

```sql
UPDATE posts SET title=?, body=? WHERE id=?
```

---

# 7️⃣ destroy → حذف بوست

```ruby
def destroy
  @post = Post.find(params[:id])
  @post.destroy

  redirect_to posts_path
end
```

SQL:

```sql
DELETE FROM posts WHERE id = ?
```

# 🎯 دورة الحياة الكاملة (Request Flow)

المستخدم يضغط Delete:

1️⃣ يروح route  
2️⃣ ينادي destroy  
3️⃣ controller يكلم model  
4️⃣ model يحذف من DB  
5️⃣ يرجع redirect للـ index

# 🔵 أهم نقطة: يعني إيه Add Column ؟

نفترض بعد شهر العميل قال:

> عايزين نضيف وصف للمنتج (description)

يعني نضيف **عمود جديد في الجدول**.

في SQL كنا هنكتب:

ALTER TABLE products ADD description TEXT;

لكن في Rails نعمل Migration جديدة 👇

---

# 🟢 7) إضافة Column جديد

rails generate migration AddDescriptionToProducts description:text

Rails فهم من الاسم 👀  
Add + To + Products

هيولد:

def change  
  add_column :products, :description, :text  
end

نشغّل:

rails db:migrate

💥 كده الجدول اتحدث بدون ما نخسر البيانات.

# 🏁 الخلاصة الكبيرة

لما تعمل Model في Rails:

1️⃣ generate scaffold  
2️⃣ migrate → إنشاء الجدول  
3️⃣ model = منطق الداتابيز  
4️⃣ controller = ال API  
5️⃣ routes = endpoints  
6️⃣ migration جديدة لأي تعديل على الجدول

وده بالظبط اللي بيحصل في الشغل 💼
