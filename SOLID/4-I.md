# تعريف ISP

> Clients should not be forced to depend on methods they do not use.

بالعربي 👇  
ما تجبرش أي كلاس إنه يطبّق ميثودز هو مش محتاجها.

يعني:  
❌ ماتعملش Interface كبير فيه كل حاجة  
✅ اعمل Interfaces صغيرة متخصصة

---

# ليه المبدأ ده موجود أصلاً؟

لأن بعض الناس تعمل كده 😅

```java
interface Worker {
    void work();
    void eat();
    void sleep();
}
```

شكله بسيط… لكن كارثة 💣  
ليه؟ لأن مش كل Worker محتاج كل الميثودز دي.

خلينا نشوف المشكلة عملياً 👇

---

# ❌ مثال يكسر ISP

## Interface ضخم

```java
interface Worker {
    void work();
    void eat();
}
```

## HumanWorker

```java
class HumanWorker implements Worker {

    @Override
    public void work() {
        System.out.println("Human working");
    }

    @Override
    public void eat() {
        System.out.println("Human eating");
    }
}
```

## RobotWorker 🤖

الروبوت ما بيأكلش 😅 
بس مجبر يطبّق الميثود!

```java
class RobotWorker implements Worker {

    @Override
    public void work() {
        System.out.println("Robot working");
    }

    @Override
    public void eat() {
        // 😭 مجبور نكتب حاجة ملهاش لازمة
        throw new UnsupportedOperationException();
    }
}
```

لو وصلت لمرحلة:

- empty method
    
- throw exception
    

🚨 اعرف إنك كسرت ISP.

---

# 🧠 المشكلة فين؟

Interface كبير بيحاول يخدم أنواع مختلفة جداً.

---

# ✅ الحل الصحيح (تطبيق ISP)

نقسم الـ Interface الكبير لInterfaces صغيرة.

---

## 1️⃣ Interface للعمل

```java
interface Workable {
    void work();
}
```

## 2️⃣ Interface للأكل

```java
interface Eatable {
    void eat();
}
```

---

## 3️⃣ HumanWorker

```java
class HumanWorker implements Workable, Eatable {

    @Override
    public void work() {
        System.out.println("Human working");
    }

    @Override
    public void eat() {
        System.out.println("Human eating");
    }
}
```

---

## 4️⃣ RobotWorker

```java
class RobotWorker implements Workable {

    @Override
    public void work() {
        System.out.println("Robot working");
    }
}
```

💥 دلوقتي الروبوت مش مجبر يطبّق eat()

وده ISP 👌

---

# مثال أقرب للـ Backend 👨‍💻

❌ Interface كبيرة للمستخدمين:

```java
interface UserService {
    void login();
    void register();
    void changePassword();
    void deleteUser();
    void generateReport();
}
```

هل كل users محتاجين كل ده؟  
أكيد لا 😅

---

# الحل

## AuthService

```java
interface AuthService {
    void login();
    void register();
}
```

## AccountService

```java
interface AccountService {
    void changePassword();
    void deleteUser();
}
```

## ReportService

```java
interface ReportService {
    void generateReport();
}
```

كل Client يستخدم اللي محتاجه فقط 🎯

---

# الفرق قبل وبعد 🔥

|قبل|بعد|
|---|---|
|Interface كبيرة|Interfaces صغيرة|
|Classes فيها methods فاضية|كل method مستخدمة|
|Coupling عالي|Coupling قليل|

---

# الخلاصة الذهبية 🏆

لو Interface فيها:

- Methods مش كل الكلاسات محتاجاها
    
- Methods بتترمي فيها Exceptions
    

🚨 قسمها فوراً.

---
