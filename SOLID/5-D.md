بص يا صاحبي، ده آخر مبدأين مهمين نربطهم ببعض في SOLID، خلينا نفهم Dependency Inversion Principle (DIP) ببساطة وبمثال Java.

## 1. يعني إيه DIP؟

Interview Answer:

> High-level modules should not depend on low-level modules. Both should depend on abstractions.

بالمصري: بدل ما كلاس يعتمد مباشرةً على كلاس تاني محدد، نخلي الاتنين يعتمدوا على `interface` أو `abstraction`.

## 2. مثال Java — التصميم الغلط

تخيل إن عندك `NotificationService` عايز يبعت إيميل:

```
class EmailService {
    public void sendEmail() {
        System.out.println("Sending email...");
    }
}

class NotificationService {
    private EmailService emailService = new EmailService();

    public void notifyUser() {
        emailService.sendEmail();
    }
}
```

المشكلة إن `NotificationService` مرتبط مباشرةً بـ `EmailService`.

لو عايز تستخدم SMS بدل الإيميل، هتحتاج تعدّل `NotificationService` نفسه.

ده اسمه Tight Coupling.

## 3. الحل — تطبيق DIP

نعمل `interface`، ونخلي كل الخدمات تعتمد على نفس الـ abstraction.

NotificationService

High-level module

MessageService (interface)

Abstraction

EmailService

Implementation

SmsService

Implementation

الكود:

```
interface MessageService {
    void sendMessage();
}

class EmailService implements MessageService {
    public void sendMessage() {
        System.out.println("Sending email");
    }
}

class SmsService implements MessageService {
    public void sendMessage() {
        System.out.println("Sending SMS");
    }
}

class NotificationService {
    private final MessageService messageService;

    public NotificationService(MessageService messageService) {
        this.messageService = messageService;
    }

    public void notifyUser() {
        messageService.sendMessage();
    }
}
```

دلوقتي أقدر أحقن أي implementation:

```
NotificationService service =
        new NotificationService(new EmailService());

service.notifyUser();
```

ولو عايز SMS:

```
NotificationService service =
        new NotificationService(new SmsService());

service.notifyUser();
```

لاحظ إننا ما عدّلناش `NotificationService` عشان نغيّر وسيلة الإرسال.

## 4. إيه علاقة DIP بـ DI؟

دي نقطة مهمة جدًا في الانترفيو:

- DIP: مبدأ تصميم بيقول اعتمد على الـ abstractions بدل الـ concrete classes.
    
- DI (Dependency Injection): أسلوب بنمرر بيه الـ dependencies للكلاس من الخارج بدل ما ينشئها بنفسه.
    

يعني في المثال، الـ DIP هو اعتماد `NotificationService` على `MessageService`، والـ DI هو تمرير `EmailService` أو `SmsService` من خلال الـ constructor.

وفي Spring Boot، الـ Spring Container يقدر ينشئ الـ beans ويحقن الـ implementation المناسبة.

الخلاصة للحفظ:

> DIP is a design principle; DI is a technique used to achieve it.
