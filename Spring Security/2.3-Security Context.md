## 🧠 يعني إيه SecurityContext في Spring Security؟

> **SecurityContext** هو المكان اللي Spring Security بيخزن فيه بيانات المستخدم بعد ما يعمل Login بنجاح.

بمعنى أبسط جدًا:  
👉 هو “ذاكرة الجلسة الأمنية” بتاعة المستخدم الحالي.

---

## 🔥 بيحتوي على إيه؟

جواه حاجة اسمها:

### 👉 Authentication object

وده بيحتوي على:

- username
    
- authorities (roles)
    
- isAuthenticated = true
    
- تفاصيل المستخدم
    

---

## 🧭 الفكرة ببساطة

لما تعمل Login:

```text
User logs in
   ↓
AuthenticationManager
   ↓
Authentication success
   ↓
SecurityContext ← بيخزن المستخدم هنا
```

---

## 💡 بعد كده بيحصل إيه؟

أي Request بعد الـ login:

- Spring بيروح يجيب الـ SecurityContext
    
- يشوف المستخدم مين
    
- يشوف صلاحياته
    
- يقرر يسمح أو يمنع
    

---

## 🧪 مثال عملي

لو عندك API:

```http
GET /api/profile
```

Spring يعمل:

```text
SecurityContext → get Authentication → get User
```

ويعرف:

- ده مين المستخدم
    
- هل داخل ولا لأ
    
- عنده صلاحية ولا لأ
    

---

## 🧩 الوصول للـ SecurityContext

```java
SecurityContext context = SecurityContextHolder.getContext();

Authentication auth = context.getAuthentication();

String username = auth.getName();
```

---

## ⚠️ مهم جدًا

- SecurityContext = per request / per session
    
- بيتخزن في:
    
    - Session (لو stateful)
        
    - أو ThreadLocal (في نفس الـ request)
        

---

## 🔐 الخلاصة

SecurityContext =

> المكان اللي Spring بيحفظ فيه “هوية المستخدم الحالي بعد تسجيل الدخول”

---

## 🧠 الصورة الكاملة

```text
Login
  ↓
AuthenticationManager
  ↓
AuthenticationProvider
  ↓
SecurityContext ← هنا بيتخزن المستخدم
  ↓
Every Request → يستخدمه للتحقق
```
