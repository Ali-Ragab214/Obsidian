# 🟩 1) UserDetailsService (Interface)

أهم Interface في سيكيوريتي كله.

## وظيفته الأساسية

تحميل بيانات المستخدم وقت تسجيل الدخول.

فيه method واحدة بس:

loadUserByUsername(String username)

Spring وقت الـ login بيقول:

> هاتلي المستخدم ده

فينادي على الـ UserDetailsService.

---

## بيرجع ايه؟

بيرجع object اسمه **UserDetails** فيه:

- username
- password
- authorities (roles / permissions)
- هل الاكونت locked ؟ expired ؟ enabled ؟

يعني كل بيانات الأمان الخاصة بالمستخدم.

---

## تستخدمه امتى؟

تستخدمه لما تعمل login system.

مثلاً:

- users في DB
- users في LDAP
- users في memory

كلهم لازم يمروا من هنا.

---

# 🟩 2) UserDetailsManager (Interface)

ده extension من UserDetailsService.

يعني:  
UserDetailsManager = UserDetailsService + إدارة المستخدمين

مش بس يقرأ المستخدم… كمان يقدر يديره.

---

## بيضيف methods زيادة 👇

createUser(UserDetails user)  
updateUser(UserDetails user)  
deleteUser(String username)  
changePassword(old,new)  
userExists(username)

يعني بقى عندك CRUD Users.

---

## الفرق المهم جداً 🔥

|Interface|يقرأ users|ينشئ users|
|---|---|---|
|UserDetailsService|✅|❌|
|UserDetailsManager|✅|✅|

---

## تستخدم UserDetailsManager امتى؟

لو عندك:

- Register endpoint
- Change password
- Admin يضيف مستخدمين

يعني أي system فيه إدارة مستخدمين.

---

# 🟩 3) Implementations (التطبيقات الجاهزة)

Spring مديلك 3 implementations جاهزين.

## 🟧 InMemoryUserDetailsManager

ده اللي انت استخدمته.

### بيخزن المستخدمين في RAM

يعني:

- للتجربة فقط
- بيروحوا لما التطبيق يقفل

### تستخدمه امتى؟

- Learning
- Testing
- Demos

مش Production.

---

## 🟧 JdbcUserDetailsManager

ده الحقيقي اللي بنستخدمه في المشاريع.

### بيخزن المستخدمين في Database

Spring بيبقى عايز جداول معينة:

- users
- authorities

ويقرأ منهم تلقائي.

### تستخدمه امتى؟

لما تعمل:

- Register
- Login
- Change password
- Roles

ده standard production approach.

---

## 🟧 LdapUserDetailsManager

ده خاص بالشركات الكبيرة.

LDAP = Active Directory

يعني login بيوزر الشركة:

- شركات
- بنوك
- شركات كبيرة

لو شغال Enterprise هتشوفه كتير.

---

# 🟩 خط سير الـ Login بالكامل 🔥

لما المستخدم يعمل login:

1️⃣ Spring يستقبل username + password  
2️⃣ ينادي AuthenticationManager  
3️⃣ ينادي UserDetailsService  
4️⃣ يجيب UserDetails  
5️⃣ يقارن الباسورد بالـ PasswordEncoder  
6️⃣ لو صح → يعمل Authentication

---

# 🧠 خلاصة تحفظها بسرعة

|المكون|وظيفته|
|---|---|
|UserDetailsService|يجيب المستخدم وقت login|
|UserDetailsManager|إدارة المستخدمين CRUD|
|InMemoryUserDetailsManager|Users في الميموري (تعلم)|
|JdbcUserDetailsManager|Users في DB (Production)|
|LdapUserDetailsManager|Users من Active Directory|

---

## أهم معلومة تختم بيها 💥

في المشاريع الحقيقية:

- هتعمل **Custom UserDetailsService**
- تقرأ المستخدم من DB باستخدام JPA.

وده اللي هنعمله لما نبدأ JWT + Register System 👌
