# 🪪 What is JWT Token ؟

**JWT = JSON Web Token**

هو **توكن مشفّر** بيستخدم في:

- Authentication (تسجيل الدخول)
    
- Authorization (تحديد الصلاحيات)
    

بدل ما السيرفر يخزن session لكل مستخدم، السيرفر بيدي المستخدم **توكن** وكل Request بعد كده يبعت التوكن معاه.

👉 اسمه **Stateless Authentication**

---

# 🎯 المشكلة قبل JWT

قديمًا كان فيه Sessions:

```
Client → Login → Server
Server → Create Session in DB
Client → sends SessionID every request
Server → Check DB every request ❌
```

المشاكل:

- يضغط على السيرفر
    
- صعب في Microservices
    
- محتاج Redis / Session storage
    

---

# 🚀 الحل = JWT

السيرفر مش بيخزن أي حاجة 😎  
بيولّد توكن فيه بيانات المستخدم نفسها.

```
Server → generates signed token → Client saves token
Client → sends token every request
Server → verifies signature فقط
```

---

# 🧠 يعني JWT عبارة عن إيه؟

JWT = **String طويل جدًا مشفّر**

مثال:

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.
eyJzdWIiOiJhbGkiLCJyb2xlIjoiQURNSU4ifQ.
sdfsdfsdFDSFDSFDSFDSFSDF
```

---

# 🧩 JWT بيتكون من 3 أجزاء

```
HEADER.PAYLOAD.SIGNATURE
```

خلينا نفصلهم 👇

---

# 1️⃣ Header

بيحدد نوع التوكن وخوارزمية التشفير.

مثال JSON:

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

بعد ما يتشفّر Base64 يبقى أول جزء.

---

# 2️⃣ Payload (المهم 🔥)

ده فيه بيانات المستخدم.

يسموها **Claims**

مثال:

```json
{
  "sub": "ali",
  "role": "ADMIN",
  "iat": 1710000000,
  "exp": 1710003600
}
```

معانيهم:

|Claim|معناه|
|---|---|
|sub|username|
|role|صلاحيات المستخدم|
|iat|وقت إنشاء التوكن|
|exp|وقت انتهاء التوكن|

⚠️ Payload مش مشفّر Encryption  
هو **Encoded فقط** (أي حد يقدر يقرأه)

الأمان الحقيقي في التوقيع.

---

# 3️⃣ Signature (أهم جزء 🔐)

السيرفر يعمل Hash باستخدام Secret Key:

```
HMACSHA256(
   base64UrlEncode(header) + "." +
   base64UrlEncode(payload),
   SECRET_KEY
)
```

لو حد عدّل payload → التوقيع يتكسر → التوكن يبقى invalid ❌

# 🎨 Diagram 1 — Token Structure

```
JWT Token
│
├── Header (algorithm)
├── Payload (user data)
└── Signature (security)
```

أو بشكل أوضح:

```
[ HEADER ] . [ PAYLOAD ] . [ SIGNATURE ]
```

# 🎨 Diagram 2 — Login Flow

```
User → POST /login (username + password)
        ↓
Spring Security authenticates
        ↓
Server generates JWT
        ↓
Server → returns token to client
```

# 🎨 Diagram 3 — Using Token in Requests

```
Client → GET /api/orders
Header:
Authorization: Bearer JWT_TOKEN
        ↓
JwtAuthenticationFilter
        ↓
Validate token
        ↓
Extract user
        ↓
Set SecurityContext
        ↓
Controller executes
```

---

# 🎨 Diagram 4 — Stateless Architecture

```
Without JWT:
Server ↔ Session DB ❌

With JWT:
Client stores token ✔
Server verifies signature فقط ✔
No DB calls ✔
```

# 🔥 ليه الشركات بتحب JWT؟

|السبب|ليه مهم|
|---|---|
|Stateless|مفيش session storage|
|سريع|مفيش DB lookup|
|مناسب للـ Microservices|كل service يقدر يفك التوكن|
|Cross-platform|Mobile + Web + APIs|

---

# ⚠️ مهم جدًا تفهمه

JWT ≠ Encryption  
JWT = Signed Token

أي حد يقدر يقرأ الـ payload لكن ما يقدرش يعدّل عليه.

---

# 🧠 الخلاصة

JWT = بطاقة هوية رقمية للمستخدم.

بدل ما السيرفر يفتكر المستخدم  
المستخدم هو اللي شايل إثبات هويته معاه.
