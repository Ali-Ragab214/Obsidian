# 1️⃣ ExtractExpiration()

```java
private Date ExtractExpiration(String token)
{
    return extractClaim(token, Claims::getExpiration);
}
```

فاكر الـ generic method اللي عملناها؟  
دي بقى أول استخدام عملي ليها 👌

إحنا وقت إنشاء التوكن حطينا:

```java
.setExpiration(new Date(System.currentTimeMillis() + JWT_EXPIRATION))
```

يعني التوكن جواه تاريخ انتهاء.

الميثود دي بتعمل:

- تفك التوكن
    
- تجيب Claim اسمه expiration
    
- ترجعه كـ Date
    

ببساطة:

> هاتلي التوكن ده بينتهي إمتى ⏰

---

# 2️⃣ isTokenExpired()

```java
private boolean isTokenExpired(String token)
{
    return ExtractExpiration(token).before(new Date());
}
```

دي عبقرية في البساطة 😄

## نشرحها بالعربي:

- `new Date()` = الوقت الحالي
    
- `ExtractExpiration(token)` = وقت انتهاء التوكن
    

الميثود `before()` معناها:

> هل التاريخ ده قبل التاريخ الحالي؟

يعني:

|الحالة|النتيجة|
|---|---|
|expiration قبل الآن|التوكن منتهي ❌|
|expiration بعد الآن|التوكن صالح ✔|

مثال:

- التوكن ينتهي 5 مساءً
    
- الوقت الحالي 6 مساءً
    

```java
5PM.before(6PM) → true
```

إذن:

```java
isTokenExpired = true
```

# 3️⃣ isTokenValid() ⭐ أهم واحدة

```java
@Override
public boolean isTokenValid(String token, UserDetails userDetails) {
   final String username = extractUsername(token);
   return (username.equals(userDetails.getUsername()) && !isTokenExpired(token));
}
```

دي الميثود اللي الـ Security Filter بيستخدمها قبل ما يسمح للـ request يدخل.

هي بتعمل **شرطين أساسيين جداً**:

---

## الشرط الأول: التوكن يخص نفس اليوزر

```java
username.equals(userDetails.getUsername())
```

ليه الشرط ده مهم؟

تخيل الهجوم ده 😈  
واحد سرق توكن بتاع User تاني وبعت Request.

Spring Security هيكون جاب الـ userDetails من قاعدة البيانات  
وإحنا جبنا username من التوكن.

لو الاتنين مش نفس الشخص → التوكن مرفوض ❌

يعني:

> هل التوكن ده معمول فعلاً لليوزر ده؟

---

## الشرط الثاني: التوكن مش منتهي

```java
!isTokenExpired(token)
```

لو التوكن expired → مرفوض فوراً.

---

## النتيجة النهائية

الميثود بترجع true فقط لو:

✔ التوكن يخص نفس المستخدم  
✔ التوكن لسه صالح زمنياً

لو شرط واحد بس فشل → false ❌

---

# الصورة الكاملة للتحقق من JWT 🧠

لما request يوصل للـ API:

1️⃣ ناخد التوكن من Header  
2️⃣ نطلع username منه  
3️⃣ نجيب userDetails من DB  
4️⃣ نتحقق:

- التوقيع صحيح (اتعمل ضمنياً)
    
- نفس المستخدم
    
- التوكن مش منتهي
    

لو كله تمام → يدخل السيستم 🎉  
غير كده → 401 Unauthorized 🚫

---

# الخلاصة السريعة

- **ExtractExpiration** → يجيب تاريخ انتهاء التوكن
    
- **isTokenExpired** → يقارن بالوقت الحالي
    
- **isTokenValid** → يتأكد إن التوكن صحيح + لنفس المستخدم
    

لو حابب نشرح بعد كده دور الـ JwtAuthFilter اللي بيستخدم الميثود دي هتفهم الصورة كاملة جدًا 👌
