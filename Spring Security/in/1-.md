# أولًا: يعني إيه Spring MVC؟

Spring MVC هو الجزء المسؤول عن استقبال الـ HTTP Request، وتشغيل الـ Business Logic، ثم إرسال الـ HTTP Response.

باختصار:

```
Browser
   |
HTTP Request
   |
Spring MVC
   |
Your Java Code
   |
HTTP Response
```

# 1) Servlet Container (Tomcat)

أول حاجة لازم تعرفها:

Spring Boot **مش بيستقبل الـ Request بنفسه**.

اللي بيستقبله هو:

```
Tomcat
```

وده اسمه

> Servlet Container

وظيفته:

- فتح Port 8080
    
- استقبال HTTP Requests
    
- إنشاء Request Object
    
- إنشاء Response Object
    
- تسليمهم لـ Spring
    

يعني:

```
Browser

↓

Tomcat

↓

Spring
```

---

# 2) Filters

أول حاجة داخل Spring تقريبًا هي الـ Filters.

```
Client

↓

Tomcat

↓

Filter
```

الفلتر بيشتغل **قبل أي حاجة**.

بيقدر:

✔ يقرأ الـ Request

✔ يعدله

✔ يمنعه

✔ يضيف Headers

✔ يضيف Logs

✔ يعمل Authentication

---

مثال:

```java
@Component
public class LoggingFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain chain)
            throws IOException, ServletException {

        System.out.println(request.getRequestURI());

        chain.doFilter(request, response);
    }
}
```

لو الـ Request:

```
GET /users
```

هيطبع:

```
/users
```

---

## أشهر استخدامات Filters

- Logging
    
- CORS
    
- JWT Authentication
    
- Compression
    
- Security
    
- Encoding

# 3) DispatcherServlet

ده أهم كلاس في Spring MVC.

هو يعتبر:

> **المخرج (Front Controller)**

كل الـ Requests بتعدي عليه.

```
Request

↓

DispatcherServlet

↓

Controller المناسب
```

هو اللي بيقرر:

> مين Controller اللي هيشتغل؟

مثلاً:

```
GET /users
```

يروح لـ

```java
@GetMapping("/users")
```

أما:

```
GET /orders
```

يروح لـ

```java
@GetMapping("/orders")
```

---

## هو بيعمل إيه؟

1. يستقبل الـ Request
    
2. يدور على الـ Controller
    
3. ينادي عليه
    
4. ياخد الـ Response
    
5. يرجعه للـ Client
    

---

# 4) Interceptor

الـ Interceptor بيشتغل **بعد DispatcherServlet** وقبل الـ Controller.

```
DispatcherServlet

↓

Interceptor

↓

Controller
```

وده بيديك 3 مراحل:

---

## preHandle()

قبل دخول الـ Controller.

مثلاً:

```java
boolean preHandle(...)
```

ممكن تعمل:

- Authorization
    
- Logging
    
- Timing
    

---

## postHandle()

بعد الـ Controller

وقبل الـ Response

---

## afterCompletion()

بعد انتهاء كل حاجة.

---

مثال

```java
public class LoggingInterceptor implements HandlerInterceptor {

    public boolean preHandle(...) {

        System.out.println("Before Controller");

        return true;
    }

    public void postHandle(...) {

        System.out.println("After Controller");

    }

}
```

---

## الفرق بين Filter و Interceptor

|Filter|Interceptor|
|---|---|
|قبل Spring MVC|داخل Spring MVC|
|بيعرف Servlet بس|بيعرف Controllers وHandler|
|يشتغل حتى لو مفيش Controller|يشتغل فقط لو فيه Handler مناسب|
|مناسب لـ CORS وSecurity والـ Logging العام|مناسب للـ Authorization، Logging الخاص، قياس زمن التنفيذ، إلخ|

قاعدة تحفظها:

> **Filter = على مستوى الـ Servlet**  
> **Interceptor = على مستوى Spring MVC**

# 5) Controller

هنا يبدأ كودك.

مثلاً:

```java
@RestController
@RequestMapping("/users")
public class UserController {

    @GetMapping("/{id}")
    public UserDto getUser(@PathVariable Long id){

        return userService.get(id);
    }

}
```

الـ Controller وظيفته:

- استقبال البيانات
    
- Validation
    
- استدعاء Service
    
- إرجاع Response
    

**المفروض مايحطش Business Logic تقيل.**

# الريكاب السريع (Interview)

احفظ التسلسل ده لأنه بيتكرر في الانترفيوهات:

```
Client
   ↓
Tomcat (Servlet Container)
   ↓
Filter
   ↓
DispatcherServlet (Front Controller)
   ↓
Interceptor (preHandle)
   ↓
Controller
   ↓
Service
   ↓
Repository
   ↓
Database
   ↑
Repository
   ↑
Service
   ↑
Controller
   ↓
Interceptor (postHandle / afterCompletion)
   ↓
Filter
   ↓
Tomcat
   ↓
Client
```

### أسئلة انترفيو مشهورة

- **ما هو DispatcherServlet؟**  
    هو الـ **Front Controller** في Spring MVC، يستقبل كل الطلبات ويوجهها للـ Controller المناسب ثم يعيد الـ Response.
    
- **ما الفرق بين Filter و Interceptor؟**  
    الـ **Filter** يعمل على مستوى الـ Servlet Container ويمكنه التعامل مع أي Request قبل دخول Spring MVC. أما الـ **Interceptor** فيعمل داخل Spring MVC حول تنفيذ الـ Controller ويعرف الـ Handler.
    
- **من الذي يستقبل الـ HTTP Request أولًا؟**  
    الـ **Servlet Container** (مثل **Apache Tomcat**) هو أول من يستقبل الطلب، ثم يمرره إلى Spring MVC.
