قبل ما تتعلم Spring Security، لازم تفهم **ليه Security موجود أصلاً**. لأن Spring Security مجرد Framework بيطبق المفاهيم دي.

---

# يعني إيه Security؟

Security هو حماية التطبيق والبيانات من أي شخص غير مصرح له أو من أي تعديل أو هجوم.

تخيل عندك تطبيق بنك.

لو أي حد قدر يدخل يشوف حسابات الناس أو يحول فلوس بدون إذن، يبقى التطبيق **مش Secure**.

هدف الـ Security هو ضمان:

- الشخص الصح هو اللي يدخل.
    
- الشخص يدخل على اللي مسموح له فقط.
    
- البيانات متتسرقش.
    
- البيانات متتعدلش.
    
- السيرفر يفضل شغال.
    

وده بيتلخص في خمس مفاهيم أساسية.

---

# 1) Authentication (التحقق من الهوية)

## يعني إيه؟

هو عملية التأكد من:

> **"مين أنت؟"**

قبل ما تستخدم أي نظام، لازم تثبت هويتك.

مثال:

لما تفتح Gmail:

```text
Email
Password
```

بعد ما تكتبهم

السيرفر يقول:

> تمام...  
> أنت فعلاً Ali.

يبقى العملية نجحت.

---

## Authentication لا يحدد الصلاحيات

هو بس بيقول:

> الشخص ده هو علي.

لكن **لسه مش عارف هيقدر يعمل إيه.**

---

## أمثلة

### Login

```text
Username

Password
```

---

### OTP

```text
Enter Code
```

---

### Fingerprint

```text
Touch Sensor
```

---

### Face ID

```text
Scan Face
```

---

### Google Login

```text
Continue with Google
```

كل دول Authentication.

---

## فى Spring Security

لما تعمل Login:

```http
POST /login
```

Spring يعمل:

```text
Check Username

↓

Check Password

↓

Authenticated
```

بعدها يخزن إن المستخدم ده دخل بالفعل (Session أو JWT حسب نوع التطبيق).

---

## سؤال انترفيو

> What is Authentication?

الإجابة:

> Authentication is the process of verifying the identity of a user.

---

# 2) Authorization (التحقق من الصلاحيات)

بعد ما عرفنا الشخص مين...

السؤال التالي:

> **هل مسموح له يعمل العملية دي؟**

---

مثال

في شركة:

عندك

```text
Ali
```

هو موظف.

هل يقدر:

- حذف الموظفين؟
    
- إضافة مدير؟
    
- تغيير المرتبات؟
    

أكيد لا.

يبقى:

Authentication نجحت.

لكن Authorization رفض.

---

## مثال في API

```http
DELETE /users/1
```

لو المستخدم:

```text
ADMIN
```

يسمح.

أما لو:

```text
USER
```

يرجع:

```http
403 Forbidden
```

---

## في Spring Security

```java
@PreAuthorize("hasRole('ADMIN')")
public void deleteUser() {

}
```

لو المستخدم Admin

✔ يدخل.

لو User

❌ يترفض.

---

## الفرق بين Authentication و Authorization

|Authentication|Authorization|
|---|---|
|من أنت؟|ماذا يسمح لك أن تفعل؟|
|يحدث أولًا|يحدث بعد نجاح Authentication|
|يتحقق من الهوية|يتحقق من الصلاحيات|
|Username + Password|Roles & Permissions|

---

## مثال من الحياة

تخيل مطار.

أول نقطة:

الضابط يشوف الباسبور.

دي:

Authentication.

بعدها:

هل عندك تصريح تدخل الـ VIP؟

دي:

Authorization.

---

# 3) Confidentiality (سرية البيانات)

تعني:

> **لا أحد يرى البيانات إلا الشخص المصرح له.**

---

مثال

لما تدخل البنك.

الرصيد:

```text
50000$
```

مين المفروض يشوفه؟

✔ أنت.

❌ أي شخص آخر.

---

## لو البيانات بتمشي على الإنترنت

بدون تشفير:

```text
Ali

password123
```

أي Hacker يقدر يقرأها.

---

لكن باستخدام HTTPS:

```text
ksjdh9283hdkd
```

كلها مشفرة.

---

## Confidentiality تتحقق بواسطة

- HTTPS
    
- SSL/TLS
    
- Encryption
    

---

مثال

بدل:

```text
Password = 123456
```

يبقى:

```text
Password = $2a$10$LKsjd983...
```

(وغالبًا التخزين بيكون **Hashing** لكلمات المرور، وليس Encryption، لأن الهدف عدم القدرة على استرجاع كلمة المرور الأصلية.)

---

## سؤال انترفيو

> Why HTTPS?

الإجابة:

حتى يمنع أي شخص من قراءة البيانات أثناء انتقالها.

---

# 4) Integrity (سلامة البيانات)

يعني:

> **البيانات لا يتم تعديلها أثناء النقل أو التخزين بدون اكتشاف ذلك.**

---

مثال

أنت حولت:

```text
100 جنيه
```

في الطريق Hacker غيرها إلى:

```text
100000 جنيه
```

دي مشكلة Integrity.

---

لازم النظام يعرف إن البيانات اتعدلت.

---

## أمثلة

- Digital Signature
    
- Hash
    
- Checksums
    
- Message Authentication Codes (MAC)
    

---

مثال بسيط

أرسلت:

```text
Hello
```

الهاش:

```text
ABC123
```

لو حد غير الرسالة:

```text
Helloo
```

يبقى الهاش يتغير.

السيرفر يعرف إن البيانات اتعدلت.

---

## مثال من Git

Git بيستخدم Hash.

لو الملف اتغير:

Hash يتغير.

وده جزء من مفهوم Integrity.

---

# 5) Availability (إتاحة الخدمة)

يعني:

> **الخدمة تظل متاحة للمستخدمين المصرح لهم عند الحاجة إليها.**

---

مثال

لو موقع البنك وقع:

```text
Server Down
```

رغم إنك Username وPassword صح...

مش هتقدر تدخل.

---

يبقى الأمن مش بس منع الاختراق.

لازم كمان:

الخدمة تفضل شغالة.

---

## التهديد الأشهر

DDoS Attack

آلاف الأجهزة تبعت ملايين الطلبات.

السيرفر يقع.

---

## الحلول

- Load Balancer
    
- Multiple Servers
    
- Rate Limiting
    
- Auto Scaling
    
- Caching
    
- Firewalls
    

---

# مثال يجمع الخمسة معًا

تخيل تطبيق بنك.

1. تدخل اسم المستخدم وكلمة المرور.
    
    - ✅ **Authentication**: يتأكد أنك أنت.
        
2. تحاول حذف حساب عميل.
    
    - ✅ **Authorization**: يرفض لأنك لست Admin.
        
3. أثناء إرسال البيانات.
    
    - ✅ **Confidentiality**: البيانات مشفرة عبر HTTPS.
        
4. أثناء التحويل.
    
    - ✅ **Integrity**: النظام يكتشف أي تعديل في البيانات.
        
5. وقت الضغط الكبير على الموقع.
    
    - ✅ **Availability**: السيرفرات الإضافية تستمر في خدمة المستخدمين.

# العلاقة بينهم

```text
               Security
                   │
     ┌─────────────┼─────────────┐
     │             │             │
     ▼             ▼             ▼
Authentication → Authorization
     │
     ▼
Confidentiality
     │
     ▼
Integrity
     │
     ▼
Availability
```

> ملاحظة: الرسم يوضح المفاهيم الرئيسية، وليس ترتيبًا زمنيًا. في الواقع **Authentication** يسبق **Authorization** أثناء طلب الدخول، بينما **Confidentiality** و**Integrity** و**Availability** هي خصائص أمنية تحيط بالنظام ككل وليست مراحل تنفيذ.

# الريكاب السريع (Interview)

احفظ الجملة دي لأنها بتتكرر كثيرًا:

|المفهوم|السؤال الذي يجيب عنه|مثال|
|---|---|---|
|**Authentication**|Who are you?|Login باستخدام Username/Password|
|**Authorization**|What can you do?|Admin فقط يستطيع حذف المستخدمين|
|**Confidentiality**|Who can read the data?|HTTPS وتشفير البيانات|
|**Integrity**|Has the data changed?|Hash وDigital Signature|
|**Availability**|Is the service available?|Load Balancer وAuto Scaling|

## أشهر أسئلة الانترفيو

**1. ما الفرق بين Authentication و Authorization؟**

- Authentication: التحقق من هوية المستخدم.
    
- Authorization: التحقق من صلاحياته بعد التأكد من هويته.
    

**2. هل يمكن تنفيذ Authorization بدون Authentication؟**

- في أغلب الأنظمة لا، لأنك لا تستطيع تحديد الصلاحيات قبل معرفة هوية المستخدم.
    

**3. لماذا نستخدم HTTPS؟**

- لحماية سرية البيانات (Confidentiality) أثناء انتقالها بين العميل والسيرفر، كما يساعد أيضًا في ضمان سلامة البيانات (Integrity) أثناء النقل.
    

بعد استيعاب هذه المفاهيم، ستجد أن كل ما ستتعلمه في **Spring Security** (مثل `SecurityFilterChain` و`AuthenticationManager` و`UserDetailsService` و`JWT` و`OAuth2`) هو مجرد تطبيق عملي لهذه المبادئ الخمسة.
