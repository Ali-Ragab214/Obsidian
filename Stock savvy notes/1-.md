# المشاكل الأربعة، واحدة واحدة

هستخدم نفس تشبيه العمارة: العمارة = النظام، كل شقة = شركة (tenant)، وكل شقة ليها مدير (`COMPANY_ADMIN`).

---

## المشكلة 1: مفيش حارس على الباب (`requireTenantId`)

**كانت إيه؟**  
الكود كان بياخد الـ tenant من `TenantContext.getCurrentTenant()`، ودي بترجع `null` لو مفيش tenant. يعني لو جه request من غير tenant، الكود كان بيكمل عادي. وفي `createUser` ده معناه إن ممكن يتعمل يوزر بـ `tenant = null`، يعني يوزر مش تابع لأي شركة، وده بيكسر الفصل بين الشركات.

**صلحناها إزاي؟**  
أضفنا `TenantContext.requireTenantId()`:

```java
public static String requireTenantId() {
    final String tenantId = CURRENT_TENANT.get();
    if (tenantId == null || tenantId.isBlank()) {
        throw new IllegalStateException("Tenant context is missing");
    }
    return tenantId;
}
```

ولو الـ tenant مش موجود، بترمي exception وتوقف العملية. اسم الفكرة: **fail closed** (لو فيه شك، ارفض). واستبدلنا بيها `getCurrentTenant()` في كل methods الـ `UserServiceImpl`.

## المشكلة 2: الكود بيدوّر في العمارة كلها وبعدين يسأل "هو من شقتي؟"

**كانت إيه؟**  
الكود كان بيعمل:

```java
User user = repository.findByIdAndNotDeleted(userId);   // يدوّر في كل الشركات
if (!user.getTenant().getId().equals(tenantId)) { ... } // وبعدين يقارن
```

المقارنة اليدوية دي كانت شغالة، فمكنش فيه تسريب مباشر. بس هي **هشة**: لو حد كتب method جديدة ونسي المقارنة، تحصل ثغرة IDOR (أدمن شركة A يوصل ليوزر شركة B بالـ id).

**صلحناها إزاي؟**  
خلينا الـ DB نفسها هي اللي تفلتر:

```java
@Query("SELECT u FROM User u WHERE u.id = :id AND u.tenant.id = :tenantId AND u.deleted = false")
Optional<User> findByIdAndTenantIdAndDeletedFalse(String id, String tenantId);
```

وعملنا helper واحد:

```java
private User loadOwned(String userId) {
    String tenantId = TenantContext.requireTenantId();
    return repository.findByIdAndTenantIdAndDeletedFalse(userId, tenantId)
            .orElseThrow(() -> new EntityNotFoundException("User not found"));
}
```

واستخدمناه في الخمس methods (get / update / delete / enable / disable). دلوقتي اليوزر بتاع شركة تانية **مش بيظهر أصلاً** في نتيجة الـ query، فمفيش مقارنة ممكن حد ينساها.

## المشكلة 3: 500 بدل 404

**كانت إيه؟**  
لو أدمن شركة A طلب id بتاع يوزر شركة B، الكود كان بيرمي `InvalidRequestException`، ومفيش handler ليها غير الـ catch-all، فالرد كان **500**. ولو الـ id بتاع `PLATFORM_ADMIN` (ملوش tenant)، كان بيحصل `NullPointerException` عند `user.getTenant().getId()` ← برضه 500.

ده مش بس شكله وحش، ده كمان بيفرّق بين الحالات (مش موجود / موجود عند حد تاني)، فبيسرّب معلومات.

**صلحناها إزاي؟**

- `loadOwned` بترمي نفس `EntityNotFoundException("User not found")` في الحالتين (مش موجود فعلاً، أو موجود في شركة تانية)، فالرد واحد.
- ضفنا في `GlobalExceptionHandler`:

```java
@ExceptionHandler(EntityNotFoundException.class)
→ HTTP 404
```

- والـ NPE اختفى لأن مفيش مقارنة على `getTenant()` تاني.

⚠️ تنبيه: الـ mapping ده بيأثر على Product / StockMvt / Tenant كمان. "مش موجود" فيهم بقى 404 بدل 500، وده تصحيح مش ضرر.

## المشكلة 4: مدير الشقة يقدر يقفل على نفسه (الأخطر)

**كانت إيه؟**  
أي `COMPANY_ADMIN` كان يقدر:

- يعطّل أو يمسح نفسه.
- يعطّل أو يمسح آخر أدمن في شركته.
- ينزّل دور آخر أدمن لـ `ROLE_USER`.

النتيجة: الشركة تفضل من غير أي أدمن، ومحدش يقدر يصلحها من جوه.

**صلحناها إزاي؟**

- `currentUserId()` بتقرا id اللي عامل الطلب من `SecurityContextHolder`.
- في `deleteUser` و`disableUser`: لو الـ target هو نفسك ← **409** (`ConflictException`).
- ونفس الاتنين + `updateUser` (للتنزيل): لو الـ target هو `COMPANY_ADMIN` نشط وعدد الأدمنز النشطين في الـ tenant `<= 1` ← **409**.
- العد بيتم بـ:

```java
countActiveByTenantIdAndRole(tenantId, ROLE_COMPANY_ADMIN)  // enabled = true AND deleted = false
```

- وعملنا `ConflictException` جديدة مربوطة بـ 409، بدل ما نستخدم `DuplicateResourceException` اللي اسمها كان هيضلل.

الأدمن لسه يقدر يعطّل أدمن **تاني** طالما فيه أكتر من واحد نشط، المنع بس للأخير.

## الخلاصة في سطر لكل مشكلة

|#|المشكلة|الحل|
|---|---|---|
|1|tenant ناقص يعدّي عادي|`requireTenantId()` يرمي exception|
|2|فلترة الـ tenant يدوية وهشة|الـ DB بتفلتر (`findByIdAndTenantId...`) + `loadOwned`|
|3|500 وNPE وتسريب وجود اليوزر|404 موحّد بنفس الرسالة|
|4|أدمن يقفل على نفسه أو على آخر أدمن|حراس 409 في delete / disable / demote|

دلوقتي لو الفكرة وضحت، نرجع لخطوات الاختبار بالـ curl؟
