# 🎯 What is a Load Balancer?

## Definition

الـ **Load Balancer** هو مكون موجود بين المستخدم والسيرفرات.

وظيفته الأساسية:

> توزيع الـ Requests القادمة من المستخدمين على أكثر من Server بدل تحميلها على Server واحد فقط.

---

## بدون Load Balancer

```text
Users
  │
  ▼
Server
```

في البداية كل شيء يعمل بشكل طبيعي.

لكن لو زاد عدد المستخدمين:

```text
10 Users     ✅
100 Users    ✅
1000 Users   ⚠️
10000 Users  ❌
```

هيبدأ السيرفر يبطأ أو يتوقف تمامًا.

---

## مع Load Balancer

```text
Users
   │
   ▼
Load Balancer
   │
 ┌─┼─┐
 ▼ ▼ ▼
S1 S2 S3
```

الـ Load Balancer يقوم بتوزيع الحمل على جميع السيرفرات.

---

# 🚀 Why Do We Need Load Balancers?

## 1️⃣ Scalability

إمكانية التوسع بسهولة.

بدل ترقية Server واحد باستمرار  وهيبقا  limited :

```text
1 Server => we upgrade resources and it will be limited and this called vertical scaling
```

يمكنك إضافة Servers جديدة:

```text
S1
S2
S3
S4
S5
```

ويسمى ذلك:

> Horizontal Scaling

---

## 2️⃣ High Availability

إذا تعطل Server واحد:

```text
S1 ❌
S2 ✅
S3 ✅
```

يبقى النظام متاحًا للمستخدمين.

---

## 3️⃣ Fault Tolerance

تقليل تأثير الأعطال على النظام.

---

## 4️⃣ Better Performance

توزيع الحمل يؤدي إلى:

- استجابة أسرع
    
- Latency أقل
    
- Throughput أعلى
    

---

# 🏆 High Availability (HA)

> [!important]  
> High Availability تعني أن النظام يظل متاحًا للعمل أغلب الوقت حتى مع وجود أعطال.

أمثلة:

- Netflix
    
- Amazon
    
- Google
    
- Meta
    

هذه الأنظمة لا يمكن أن تتوقف لساعات.

# 1️⃣ DNS Load Balancing

---

# 🌎 What is DNS?

DNS اختصار لـ:

**Domain Name System**

ويعتبر:

> مترجم الإنترنت

---

البشر يتذكرون:

```text
google.com
```

بينما الحواسيب تتعامل مع:

```text
142.250.x.x
```

لذلك يقوم DNS بتحويل:

```text
google.com
```

إلى:

```text
IP Address
```

---

# DNS Resolution Flow

```text
Browser
   │
   ▼
DNS Resolver
   │
   ▼
DNS Server
   │
   ▼
IP Address
   │
   ▼
Target Server
```

---

# How DNS Load Balancing Works

بدل أن يعيد DNS عنوان IP واحد:

```text
skillhub.com
     │
     ▼
192.168.1.1
```

يعيد عدة عناوين:

```text
skillhub.com

192.168.1.1
192.168.1.2
192.168.1.3
```

---

# Round Robin Distribution

```text
Request 1 → S1
Request 2 → S2
Request 3 → S3
Request 4 → S1
Request 5 → S2
```

---

## ✅ Advantages

### Simple

سهل جدًا في الإعداد.

### Cheap

غالبًا متاح مع مزود الـ DNS.

---

## ❌ Disadvantages

### No Health Checks

لا يعرف إذا كان السيرفر متوقفًا أم لا.

مثال:

```text
S1 ❌
S2 ✅
S3 ✅
```

قد يرسل مستخدمين إلى S1 رغم أنه متوقف.

---

### Weak Traffic Intelligence

لا يعرف:

- CPU Usage
    
- RAM Usage
    
- Response Time
    
- Network Load
    

---

### Security Concerns

يكشف IP الحقيقي للسيرفرات للمستخدمين.

---

### DNS Caching Problems

أحيانًا يحتفظ الجهاز بالـ IP لفترة طويلة (TTL).

بالتالي قد يستمر المستخدم في الذهاب لنفس السيرفر.

# ❤️ Health Checks

واحدة من أهم المميزات.

كل فترة زمنية:

```text
Every 5 Seconds
```

يقوم الـ Load Balancer بإرسال Ping أو HTTP Request للسيرفرات.

مثال:

```text
GET /health
```

---

إذا كان الرد:

```text
200 OK
```

فالسيرفر سليم.

---

إذا لم يرد:

```text
Timeout
500 Error
Connection Refused
```

فيتم استبعاده من التوزيع.

---

مثال:

```text
S1 ❌
S2 ✅
S3 ✅
```

يصبح:

```text
Traffic → S2
Traffic → S3
```

فقط.

# 🔄 Load Balancing Algorithms

## 1. Round Robin

```text
S1 → S2 → S3
```

بالتتابع.

---

## 2. Least Connections

يختار السيرفر صاحب أقل عدد اتصالات نشطة.

مثال:

```text
S1 = 200 Connections
S2 = 30 Connections
S3 = 15 Connections
```

الطلب الجديد يذهب إلى:

```text
S3
```

---

## 3. Weighted Round Robin

إذا كانت قدرات السيرفرات مختلفة:

```text
S1 = 16 CPU
S2 = 8 CPU
S3 = 4 CPU
```

نعطي أوزان:

```text
S1 = 50%
S2 = 30%
S3 = 20%
```

فيستقبل S1 طلبات أكثر.

---

## 4. IP Hash

نفس الـ IP يذهب دائمًا لنفس السيرفر.

---

مثال:

```text
User A → S1
User A → S1
User A → S1
```

---

# Sticky Sessions

تسمى أيضًا:

```text
Session Affinity
```

---

إذا سجل المستخدم الدخول على:

```text
S2
```

يبقى على:

```text
S2
```

طوال الجلسة.

---

تستخدم عندما تكون الـ Session مخزنة داخل السيرفر نفسه.

---

# SSL Termination

ميزة مهمة جدًا.

بدل أن تقوم كل السيرفرات بفك تشفير HTTPS:

```text
HTTPS
```

يقوم Load Balancer بذلك مرة واحدة.

---

```text
Client
   │ HTTPS
   ▼
Load Balancer
   │ HTTP
   ▼
Servers
```

---

هذا يقلل استهلاك الموارد على السيرفرات.

---

# Reverse Proxy vs Load Balancer

|Reverse Proxy|Load Balancer|
|---|---|
|يخفي السيرفرات|يوزع الحمل|
|Security|Scalability|
|Caching|Traffic Distribution|
|SSL Termination|Health Checks|

---

> [!tip]  
> NGINX يمكن أن يعمل كـ Reverse Proxy و Load Balancer في نفس الوقت.

## Benefits

# 🔥 Layer 4 vs Layer 7 Load Balancer

|Layer 4|Layer 7|
|---|---|
|TCP/UDP|HTTP/HTTPS|
|أسرع|أذكى|
|يعتمد على IP و Port|يفهم URL و Headers|
|استهلاك أقل|Features أكثر|

---

## Layer 7 Example

```text
/api/users
      │
      ▼
User Service
```

```text
/api/orders
      │
      ▼
Order Service
```

الـ Load Balancer يفهم محتوى الـ URL ويوجه الطلب بناءً عليه.

# 🎤 Interview Questions

## What is a Load Balancer?

A component that distributes incoming traffic across multiple servers to improve scalability, availability, and reliability.

---

## Why do we use Load Balancers?

- Scalability
    
- High Availability
    
- Fault Tolerance
    
- Better Performance
    

---

## What is Health Check?

Mechanism used to verify whether backend servers are healthy before routing traffic to them.

---

## What is Sticky Session?

Keeping a user connected to the same backend server during a session.

---

## Why is DNS Load Balancing considered weak?

- No Health Checks
    
- DNS Caching Issues
    
- Limited Traffic Intelligence
    
- Exposes Server IPs
    

---

## Difference between Layer 4 and Layer 7?

Layer 4 uses network information (IP/Port).

Layer 7 understands application protocols such as HTTP and HTTPS.
