### الحالة الثانية (ودي المشكلة الحقيقية)

الـ Request وصل للسيرفر.

↓

السيرفر نفذ العملية.

↓

خصم الفلوس.

↓

حفظ البيانات.

↓

لكن الـ Response مرجعش للـ Client بسبب:

- Network Failure
- Timeout
- Connection Lost
- أو أي مشكلة أثناء إرسال الـ Response.
الـ Client هيعتقد إن العملية فشلت، فيبعت نفس الـ Request مرة تانية.

**لو معندناش Idempotency، السيرفر هينفذ العملية مرة تانية وهيخصم الفلوس مرتين.**
### الحل

بنولد **Idempotency Key** (غالبًا UUID) **لكل عملية Business** (مثل عملية دفع واحدة)، ونبعته مع الـ Request في الـ Header.

مثال:

```
POST /paymentsIdempotency-Key: 8f3b5d...
```

لما السيرفر يستقبل الـ Request:

- لو الـ Idempotency Key **مش موجود**، ينفذ العملية ويحفظ المفتاح.
- لو نفس الـ Idempotency Key وصل مرة تانية، يعرف إن دي إعادة إرسال لنفس العملية، **فمش ينفذهاش مرة تانية**.

وبكده بنمنع **Duplicate Requests** أو بالأدق **Duplicate Processing** لنفس العملية.
