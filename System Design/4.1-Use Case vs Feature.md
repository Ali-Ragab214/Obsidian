ببساطة يا علي، **Use Case في System Design** هو:

> **وصف لعملية أو هدف يريد الـ User أو Actor أن يحققه باستخدام الـ System.**

يعني بنسأل:

**"المستخدم عايز يعمل إيه بالـ system؟"**

### مثال: E-commerce System 🛒

عندك User، ممكن يعمل:

- Register
    
- Login
    
- Search Products
    
- Add Product to Cart
    
- Place Order
    
- Pay for Order
    
- Track Order
    
- Cancel Order
    

كل واحدة من دول تعتبر **Use Case**.

مثلاً:

> **Place Order**

الـ Use Case ممكن يكون:

```text
Actor: Customer

Use Case: Place Order

1. Customer chooses products
2. System validates product availability
3. Customer provides shipping address
4. System calculates total price
5. Customer pays
6. System creates the order
7. System sends confirmation
```

### طيب إيه الفرق بين Use Case و Feature؟

الفرق بسيط لكن مهم:

**Feature** = capability موجودة في النظام.

**Use Case** = **السيناريو/الهدف الذي يستخدم فيه الـ Actor هذه capability لتحقيق شيء معين.**

مثلاً:

```text
Feature:
Payment System

Use Cases:
- Customer pays for an order
- Customer gets a refund
- Admin verifies a payment
```

### في System Design بنستخدم الـ Use Cases ليه؟

لأنها بتساعدك تحدد **إيه اللي السيستم المفروض يعمله قبل ما تبدأ ترسم Architecture**.

مثلاً لو بنصمم **YouTube**:

```text
Actors:
- User
- Creator
- Admin

Use Cases:
User:
  - Sign up
  - Watch video
  - Search videos
  - Like video
  - Subscribe to channel

Creator:
  - Upload video
  - Edit video
  - Delete video
  - View analytics

Admin:
  - Moderate content
  - Ban user
```

بعد ما تحدد الـ Use Cases، تبدأ تسأل:

**"إيه الـ components/services اللي محتاجها عشان أحقق الـ Use Cases دي؟"**

ومن هنا تبدأ تدخل في:

`Requirements → Use Cases → APIs → Components/Services → Database → Scaling → Architecture`

فـ **Use Case هو الـ business action/goal من وجهة نظر الـ Actor**، وليس مجرد endpoint أو class في الكود.
